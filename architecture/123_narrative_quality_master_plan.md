# 123. 대사·서사 품질 개선 마스터 계획 (2026-09-25)

> 상태: **부분 구현 / 두 팩 단기 실런 일부 검증, 출시 관문 미통과** (2026-09-25). 근거: [[architecture/122_narrative_reader_experience_observations|독자 경험 관찰 기록]].
> 범위: 저작 팩 `graymar_v1`·`star_sand_v1`의 일반 독자 경험. 판정·월드 상태는 서버 정본, LLM은 그 결과를 표현한다는 기존 원칙을 유지한다.
> 목표: 문장만 윤문하는 프로젝트가 아니다. **행동 → 사건·단서·관계 변화 → 그 변화를 반영한 대사와 다음 선택 → 누적된 결말**을 독자가 끊김 없이 따라갈 수 있게 한다.

## 0. 완료의 정의와 변경 원칙

처음 읽는 사람이 매 장면 뒤에 다음 네 질문에 답할 수 있어야 한다. **지금 어디에 있는가? 방금 무엇을 시도했고 실제로 무엇이 일어났는가? 새로 알거나 잃은 것은 무엇인가? 그래서 다음에 할 수 있는 일은 무엇인가?** 이 네 질문의 답을 오직 내부 상태나 로그가 아니라 화면에 나온 본문·선택지에서 찾을 수 있어야 한다. 의도적인 비밀·실패·NPC의 거절은 허용하지만, 그 사실 자체와 이유·후속 방향은 읽혀야 한다.

계획을 실행할 때 지킬 경계:

1. **새 기능보다 정합 우선.** 기존 `EventChoiceGate`, `QuestForwardChoice`, `EmptyHandedHint`, 대화 잠금, 아크 3막(arch/98·103·104·110)을 먼저 추적한다. 이미 있는 장치를 복제하거나 규칙 문장만 추가하지 않는다.
2. **서버 사실을 서술이 결정하지 않는다.** `locationId`, 행동 판정, NPC 정체, 퀘스트 사실, 비용·보상, 엔딩 루트는 서버/콘텐츠 정본이다. 서술에서 새 수치·증거·이동·거래를 꾸며 상태에 역수입하지 않는다.
3. **확정 결함과 감상·가설을 분리한다.** N-10/11/13의 실제 표면 어긋남은 우선 다루되, N-12/14/16은 과거 표본 또는 후속 코드 변경이 있으므로 현행 재현을 먼저 확인한다. 재현되지 않으면 예방 테스트만 남기고 수정 범위를 늘리지 않는다.
4. **모델 호출 수 증가를 기본 해법으로 삼지 않는다.** 선택지·대사 연결에 필요한 서버 정본 데이터와 이미 생성된 결과를 먼저 활용한다. 추가 JEV/nano/메인 호출은 정확도·지연·운영 복잡성의 실측 이득을 확인한 뒤 별도 결정한다.
5. **기존 장점을 보존한다.** N-01의 사건형 오프닝, 장면 고유 사물을 이용한 선택지, NPC별 말투와 팩별 분위기, 자유 탐험을 없애지 않는다. ‘모든 턴에 강제 사건’이나 ‘모든 NPC가 즉시 정답 공개’로 해결하지 않는다.

## 2. 실행 순서와 의존 관계

```text
P0 현행 기준선·재현
  → P1 장면/행동/선택지 정합
  → P2 정본 사실/대사 표면 정합
  → P3 대화·단서·후속 선택의 진전
  → P4 첫인상·이동 리듬
  → P5 결말의 선택·대가·파급 효과
  → P6 문장 리듬과 표면 마감
  → P7 두 팩 통합 검증·출시 판단
```

이 순서의 이유는 간단하다. 엉뚱한 선택지나 장소가 나오는 상태에서 대사만 개선하면 그 문장도 독자가 믿지 못한다(P1). 사실의 정본이 흔들리면 대화 진전을 설계할 수 없다(P2). 단서와 다음 행동의 연결이 생긴 다음에야 첫 10턴의 길이·이동을 줄여도 정보 손실을 판단할 수 있다(P3→P4). 결말은 그 앞에서 축적한 선택을 소비하므로 뒤에 검증한다(P5). 문장 취향 문제는 구조 변경이 끝난 뒤 마지막에 다뤄 재작업을 줄인다(P6).

### P0. 기준선 고정 및 현행 재현 — 부분 확인

**목적:** 관찰 문서의 9/2~9/22 표본과 실제 수정 시작 시점의 코드를 분리한다.

- 시작 시 `root`·`server`·`client` 각각의 HEAD, 원격 대비 상태, 미커밋 파일을 기록한다. 현재 작업트리의 다른 변경은 사용자 자산으로 보존한다. 로컬/원격 테스트 서버의 실제 버전도 확인해 코드와 런이 같은 해시인지 표시한다.
- N-10은 한 턴의 `eventId`·현재 장소·주 NPC·`choiceSurface`·노출 `choiceIds`·`llmChoices`·최종 UI 선택지를 함께 추적한다. 과거 기록에서 서술은 회계사 장면, `choiceSurface=server`와 `mkt_enc_bus_*`는 악사 이벤트, `llmChoices`는 회계사 중심이었다. **두 후보 중 어느 것을 왜 최종 노출했는지**가 핵심이다.
- N-11은 저작 이벤트 `EVT_GUARD_INT_3`가 경비대 지구 외곽 술집을 배경으로 한다는 점을 포함해, 입구→술집의 이동이 이벤트 선택·프롬프트·본문 중 어디에서 생략됐는지 확인한다. 단순히 “다른 장소 이벤트 오매칭”으로 단정하지 않는다.
- N-12, N-14, N-16은 현행 재현 여부를 따로 기록한다. N-14는 서버의 최근 화자 후처리 커밋 이후 스트리밍·완료 본문 양쪽을 본다. N-16은 현재 아크 스테이지/명시적 피날레 선택(arch/103)을 거치는 완주로 확인한다.
- 자동 점수만 보지 않고 **행동 입력 → 서버 판정/상태 → 최종 본문 → 실제 노출 선택지**를 같은 턴에 나란히 놓는 읽기용 비교표를 만든다. 개인 계정·실유저 데이터는 쓰지 않는다.

**산출물:** 재현 여부와 최신 해시를 적은 표; 대표 고정 픽스처(회계사 협박, 경비대 외곽 술집, 이렌 공통몽, 행동 강행, 화자 경계, 피날레). **통과 조건:** N-10~16 각각에 `현행 재현 / 해소됨 / 조건부 / 판단 보류`와 근거가 붙는다. 보류를 결함 확정으로 넘기지 않는다.

### P1. 장면·행동·선택지의 단일 정합 — 부분 구현·일부 실런 확인

**대상:** N-10, N-11, 현행 재현 시 N-12.

1. LOCATION 턴에서 이미 서버가 가진 `locationId`, 활성 `eventId`, `primaryNpcId`, 플레이어 입력/판정, 선택지 출처를 **한 턴 계약**으로 명시한다. 새 게임 상태를 만들어 저장하는 것이 아니라, 기존 값이 서버 기본 선택지·LLM 선택지·서술 프롬프트·최종 UI까지 어떻게 흐르는지 확인하고 어긋나는 지점을 좁힌다.
2. 서버 기본 선택지와 워커의 `finalChoices` 중 무엇이 유저에게 노출되는지 단일 경로로 추적한다. 현재 `EventChoiceGate`는 NPC 일치만 보는 경우가 있으므로 **NPC가 없거나 다른 이벤트의 선택지가 남는 사례**까지 검증한다. 선택지 자체의 `sourceEventId`/장면 출처를 확인하는 방안은 진단 후 최소 변경으로 결정한다. 오해를 막기 위해 선택지 라벨만 기계적으로 다른 이름으로 치환하지 않는다.
3. 이벤트가 현재 구역 안의 **하위 무대**(경비대 외곽 술집 등)로 옮길 때는 본문 첫머리의 장소 연결을 명시한다. 실제 위치 상태가 바뀌지 않는 사건이라면 그 범위도 문장에서 분명해야 한다. 프롬프트의 기존 `sceneFrame` 연속성 규칙을 우선 확인한다.
4. 강한 자유 입력은 서버 판정 결과에 맞춰 **시도 → 상대·세계의 반응 → 결과**가 최소 한 번 드러나도록 한다. 싸움을 반드시 성공시키거나 전투로 강제하지 않는다. 무산·저지·실패도 플레이어 행동에 대한 구체적 결과여야 한다.

**코드 탐색 시작점:** `server/src/turns/location-turn.service.ts`의 이벤트/선택지 조립, `turns.core.ts`·`event-choice-gate.spec.ts`, `engine/hub/event-matcher.service.ts`·`npc-resolver.service.ts`, `llm/llm-worker.service.ts`의 최종 선택지 저장, `content/*/events_v2.json`. **선행 설계:** arch/68, arch/98, arch/104·105.

**통과 조건:** N-10/11 고정 픽스처에서 본문과 실제 노출 선택지의 무대·상대가 맞고, 하위 무대로 옮기는 경우 연결 문장이 보인다. N-12가 현행 재현되면 행동이 단순 언급에 그치지 않는 회귀 테스트가 통과한다. 10~15턴 표적 런에서 심각한 장면·선택지 불일치 0건. 기존 자유 입력·NPC 소개·경비대 이벤트의 의도된 동선은 유지한다.

### P2. 사실 정본·화자 경계 보호 — 정본 부분 수정·일부 실런 확인

**대상:** N-13, 현행 재현 시 N-14. N-08의 중요한 숫자도 여기서 정본 여부를 분류한다.

1. 이렌의 공통몽에서 **사흘간 깨어나지 못했다**는 정본을 `facts.json`·`npcs.json`·프롤로그·관련 이벤트/프롬프트·요약 메모리까지 대조한다. 내용이 다른 저작 지점이 있으면 먼저 정본을 통일하고, 생성 결과의 역전(못 잠 ↔ 못 깨어남)은 고정 재현으로 막는다. 의도적인 거짓말이라면 명시적 화자 동기·후속 폭로가 있는 경우만 예외로 둔다.
2. 숫자·시점·가격처럼 **정확히 기억해야 하는 단서**와 분위기용 세부를 구분한다. 핵심 사실은 식별 가능한 fact/상태를 출처로 삼고, 실제 단서가 아닌 임의의 정확한 숫자를 새 퀘스트 정보처럼 부풀리지 않는다. 숫자 자체를 전면 금지하지 않는다.
3. N-14가 현행 재현되면 최근 JEV 기반 화자 후처리와 기존 `narrative-postprocess`의 스트리밍 경계·익명 화자·완료 본문 경로를 함께 본다. 메인 서술의 대사 형식과 UI 렌더링은 별개로 검증한다. 비대사 인용이나 간접화법을 NPC 대사로 오귀속시키지 않는다.

**코드·콘텐츠 탐색 시작점:** `content/star_sand_v1/facts.json`, `npcs.json`, `scenario.json`, `server/src/llm/prompts/prompt-builder.service.ts`, `llm/worker/narrative-postprocess.service.ts`, `llm/narrative-filter.core.ts`. **통과 조건:** 정본-본문 역전 0건(표적 픽스처와 두 극야해안 단기 런); 화자 문제는 현행 재현 시 스트리밍·완료 렌더 양쪽에서 대사 누락·오귀속 0건. 단서 사실과 일반 비유를 혼동하는 검사는 오탐을 먼저 검토한다.

### P3. 대화 → 새 사실/관계 → 다음 행동의 연결 — 부분 구현·오유도 재검증 중

**대상:** N-05, N-06, N-07, N-08.

1. 같은 NPC와 2~4턴 이어 말한 표본을 `질문`, `이미 공개된 fact`, `이번 턴의 판정`, `실제 새 fact/관계/현장 변화`, `NPC가 알 수 있는 것`으로 읽는다. 현재 구현된 `EmptyHandedHint`·`QuestForwardChoice`·`recentTopics`·대화 잠금이 왜 범용 선택지 또는 재암시로 귀착했는지 **원인별로 나눈 뒤** 바꾼다.
2. 대화 턴은 새 사실을 항상 강제하지 않는다. 합당한 반응의 경로를 `직접 답변`, `부분 답변과 확인 가능한 단서`, `관계/태도 변화`, `이유가 있는 거절과 특정 다음 경로`로 나눠 본문에서 하나 이상 읽히게 한다. 모르는 NPC가 증거를 지어내지 않게 보유 지식·공개 조건을 유지한다.
3. 사실을 얻거나 명확한 인계를 받은 다음에는 그 턴의 **실제 대상/사물/장소**를 참조하는 선택지를 최소 하나 고려한다. 선택지가 장면 고유 행동을 표현해도 `sourceNpcId`, affordance, 위험도, 클릭 후 판정이 일치해야 한다. 자유 입력은 대체하지 않는다.
4. 에드릭처럼 숫자를 쓰는 인물은 숫자가 `정본 단서`, `개인의 추정`, `단순 습관적 말버릇` 중 무엇인지 독자가 구분할 단서를 준다. 정본이 아닌 정밀 수치로 추리 퍼즐을 꾸미지 않는다.

**코드 탐색 시작점:** `server/src/engine/hub/quest-progression.service.ts`, `server/src/turns/empty-handed-hint.core.ts`·`quest-forward-choice.core.ts`, `llm/prompts/prompt-builder.service.ts`, `llm/nano-event-director.service.ts`, `llm/worker/worker-narrative.core.ts`. **선행 설계:** arch/45·98·104와 9/2 빈손 대화 가드.

**통과 조건:** 이렌·에드릭을 각각 연속 대화하는 표적 런을 정독했을 때 매 턴 답변/변화/정당한 거절 중 무엇이 일어났는지 구분할 수 있고, 같은 화제의 재암시가 새 사실처럼 반복되지 않는다. 단서 획득 후 행동 가능한 경우 다음 선택지에 장면 고유 후속 행동이 있다. 범용 선택지 빈도는 P0 기준선과 **동일 분모·동일 선택지 표면**으로 비교한다. 무의미한 선택지 치환이나 NPC 정보 누출로 수치를 개선하면 불합격이다.

### P4. 시작 장면의 동기와 이동 턴의 리듬 — 부분 구현·일부 실런 확인

**대상:** N-02, N-03, N-04. N-01은 보존 게이트.

1. 그레이마르는 로넨과 장부가 **누구에게 어떤 위험**을 주는지 초반 본문에서 하나의 구체적 결과로 읽히게 한다. 정본 밖의 새 범죄·사형 확정·거액 보수를 추가하지 않는다. 신비가 필요한 정보와 첫 행동의 동기를 구별한다.
2. 극야해안의 여관 재진입은 막지 않는다. 선택 시 “방금 나왔던 장소에 다시 들어가 확인할 이유”가 장면이나 선택지에서 읽히게 한다. 이미 알려진 상태를 반복 낭독하기보다 여관 안에서만 확인 가능한 사물·인물에 집중한다. `hub` 추상 공간과 실제 여관의 이름/위치 구분(arch/92)을 회귀시키지 않는다.
3. 단순 이동은 시간·지형을 짧게 연결하고, **실제 있는 경우에만** 변화한 사람·상태·위험을 전면에 둔다. 사건이 없는 모든 이동에 새 사건을 강제로 붙이지 않는다. 이동 비용·시간대와 플레이어의 장소 선택권은 기존 서버 규칙대로 둔다.

**통과 조건:** 두 팩 신규 진입 10~15턴 정독에서 의뢰 이유를 한 문장으로 재설명할 수 있고, 동일 장소 재방문이 의도적 행동으로 보인다. 이동·진입 본문이 직전 위치/시간대와 모순되지 않으며, 짧아져도 다음 장면의 공간 이해를 해치지 않는다. 첫 장면의 공포·항구 분위기(N-01)는 유지된다.

### P5. 결말의 인과와 체감 보상 — 미착수

**대상:** N-16(현행 재현에 따라 범위 결정).

- 먼저 현재 코드로 명시적 `arc_finale`까지 가는 **완주 표본**을 확보한다. 9/2 기록의 150↔20골드·결말 추상성은 회귀 후보이지 현행 결함 확정이 아니다.
- 현재 `ArcState`·stageProgress·ending reason·선택된 루트·확정된 비용/보상과 결말 본문을 대조한다. arch/103의 **커밋 후 3막 → “결말을 맞이한다” 명시 선택지**를 다시 설계하지 않는다.
- 결말 본문은 `선택한 루트`, `핵심 증거의 귀착`, `직접 관계된 NPC 또는 세력의 즉각적 변화`, `지불한 대가`, `남는 불확실성`을 우선순위 순으로 드러내는 계약을 세운다. 모든 갈래를 같은 여운 문단으로 평탄화하지 않는다. 서버가 확정하지 않은 처벌·금액·아이템은 단정하지 않는다.

**통과 조건:** 두 팩에서 가능한 루트/안전망을 대표하는 완료 경로로 테스트한다. 구체 비용·선택·엔딩 루트와 본문 충돌 0건, 종결권이 플레이어에게 있다는 UI 계약 유지, 결말 뒤 독자가 “내 선택으로 무엇이 달라졌나”를 두 문장으로 말할 수 있다. 긴 테스트는 엔딩 검증 목적을 명시하고 수행한다.

### P6. 문장 리듬·표면 마감 — 지시 부분 수정·일부 실런 확인

**대상:** N-09, N-15. N-14의 현행 재현 여부도 최종 확인한다.

- 구조 수정 이후 동일한 장소·NPC 연속 턴을 다시 읽고, 새 정보 없이 붙은 감각 묘사만 줄인다. 환경 묘사를 제거하는 것이 아니라 **행동·반응·발견 안에 감각을 묶는 방향**이다.
- 이미 있는 arch/110의 개시 변주와 `scripts/analyze_narrative_structure.py`를 재사용한다. 금지어 목록·완성 문장 예시를 프롬프트에 늘리지 않는다(구체 어휘 주입의 복제 위험, 불변식 50). `냄새/시선/손끝` 출현 횟수는 경향 확인용이고 단독 통과 지표가 아니다.
- 영어 잔해, 인용부호 연결, 화자 불명확 문장을 `scripts/audit_quality.py`의 정본 감사와 실제 본문 정독으로 확인한다. 후처리로 의미를 바꾸거나 비대사를 화자 마커로 포장하지 않는다.

**통과 조건:** 같은 NPC의 연속 대화에서 매 턴 공간이 처음부터 리셋되는 느낌이 줄고, 필수 단서·인물 어조는 보존된다. 언어·따옴표 오류 0건(표적 픽스처), 자동 품질 감사와 사람이 읽는 문장 모두 통과. 분량·반복 지표가 좋아져도 사건 정보가 누락되면 불합격이다.

### P7. 통합 검증과 출시 판단 — 미착수

- P1~P6을 합친 두 팩의 신규 진입, 3턴 이상 동일 NPC 대화, 다른 지역 이동, 강행 자유 입력, 단서 획득, 종반 경로를 통합 정독한다. 가능한 한 `chatty`·`coercer`·관찰 성향을 섞고 **표준 플레이테스트는 10~15턴 여러 런**으로 누적한다. 완주만 별도 긴 런을 쓴다.
- 서버/클라 변경 레포에서 각각 필요한 테스트와 `pnpm build`를 돌린다. 정본 `scripts/playtest.py`의 V0~V14, `scripts/audit_quality.py <run_id>`, 콘텐츠 정합 감사, 기존 스냅샷의 **diff 내용**을 함께 검토한다. 자동 PASS는 독자 경험 PASS로 간주하지 않는다.
- 변경 전후를 같은 시나리오·행동 유형·모델 설정·선택지 표면으로 비교한다. 속도/비용/프롬프트 예산도 함께 본다. 핵심 경로에 LLM 호출을 늘렸다면 지연 p50/p95와 실패율의 악화가 정성 이득보다 크지 않은지 별도 승인 관문을 둔다.
- 이 계획과 관찰 문서의 N-01~16에 `해결/완화/현행 미재현/미해결`을 실제 근거와 함께 갱신한다. 개선이 증명되지 않은 항목을 완료 처리하지 않는다.

**최종 출시 조건:** P0에서 확정된 심각한 장면·사실 정합 결함의 재발 0건, 두 팩의 연속 대화와 이동 경로에서 네 독자 질문에 답할 수 있음, 명시적 결말의 상태-서술 일치, 기존 테스트·빌드·품질 게이트 통과. 배포·푸시는 해당 시점의 별도 작업 범위와 서버 상태를 확인한 후 진행한다.

## 3. 회차 운영 규칙

한 단계는 **현재 재현 → 원인 추적 → 최소 범위 구현 → 표적 테스트 → 10~15턴 실런 정독 → 필요 시 재수정 → 해당 단계만 로컬 커밋**이 끝나야 한 사이클이다. 테스트만 3회 돌리거나 문서만 고쳐서는 완료가 아니다. 단계가 실패하면 다음 단계로 넘어가지 않고 같은 단계에서 고친다. 서로 다른 레포의 변경이 한 기능을 이루면 버전·배포 순서를 명시해 중간 상태에서 깨지지 않게 한다.

| 단계 | 상태 | 다음 단계 진입 게이트 |
|---|---|---|
| P0 기준선 | 부분 확인 | 현재 코드 해시·재현 분류·고정 픽스처 확보 |
| P1 장면/행동/선택지 | N-10·11 지목 경로 실런 통과, 의도된 레닉 첫 조우 대기 | N-10/11 및 재현된 N-12 표적 회귀 0 |
| P2 사실/화자 | 정본 부분 수정·N-13 실런 확인, N-14 대기 | N-13 정본 충돌 0, N-14 현행 상태 결정 |
| P3 대화/선택 진전 | N-17 후속 이동 오유도 수정·실런 통과, 대화 진전 본관문 대기 | 같은 NPC 연속 대화에서 정보·관계·정당한 거절이 분별됨 |
| P4 도입/이동 | 부분 구현·단기 실런 확인 | 첫 행동의 이유·재방문 목적·이동 연결이 읽힘 |
| P5 결말 | 미착수 | 현행 완주 표본의 선택·비용·파급 효과 정합 |
| P6 문장 마감 | N-18 최종 본문·스트림 방어 단위 검증, 실런 미재현 | 핵심 정보 보존 + 표면 오류·정형감 재검토 |
| P7 통합/출시 | 미착수 | 두 팩 정독, 테스트·빌드·감사, 전 항목 상태 갱신 |

각 단계의 결과는 이 표의 상태뿐 아니라 **기준 커밋, 변경 커밋, 재현 파일·런 ID, 실패/통과 근거, 남은 위험**을 문서에 남긴다. 실행 중 다른 결함이 발견되면 기존 단계에 억지로 끼우지 말고 N-번호를 새로 부여해 심각도와 의존 관계를 재평가한다.
