## 문제

극야해안 선택지 60번 `내일 새벽 뒷마당에 가겠다고 답한다`는 이렌에게 하는 `TALK`다. 실제 클릭 뒤에도 이렌과 대화가 이어졌다. 선택지에는 목표 시각이나 목적지 ID가 없다. 현재 `REST`는 고정 2틱을 쓰며, `뒷마당`은 `content/star_sand_v1/locations.json`의 이동 장소가 아니다. 따라서 플레이어가 `새벽까지 기다려 뒷마당으로 간다`고 입력해도 정본 시계와 위치가 함께 바뀐다고 보장할 수 없다. 서술만 뒷마당에 도착했다고 쓰는 것으로는 이 문제를 해결하지 못한다.

## 구현할 행동 계약

- 약속과 실행을 구분한다. `내일 가겠다`는 대화이며, 실제 대기·이동은 플레이어의 별도 행동으로 처리한다. 약속을 추적할지는 설계 시 결정한다.
- `특정 시간대까지 기다린 뒤 장소로 간다`는 복합 행동의 시간 목표와 이동 목표를 구조화한다. 서버가 목표를 검증하고 `globalClock`, `day`, `phaseV2`, 현재 장소·장면을 함께 갱신한다. LLM 서술은 확정된 결과만 받는다.
- 여관의 뒷마당 같은 같은 장소 안의 세부 공간을 어떤 상태로 표현할지 결정한다. 별도 `LOCATION` 등록과 장소 내부 장면 상태를 비교한다. 어느 쪽이든 저장·이어하기와 NPC 시간표가 같은 위치를 가리켜야 한다.
- 대기가 가능한 길이, 중간 사건·위험, 행동 비용, 이동 불가 시 응답을 정한다. 유효하지 않은 세부 목적지를 거점 복귀로 바꾸거나 서술에서만 순간이동시키지 않는다.

## 완료 조건

1. 60번 같은 약속 선택지를 클릭해도 시간이 즉시 새벽으로 건너뛰거나 장소가 바뀌지 않는다.
2. 실제 대기·이동 행동은 다음 새벽과 유효한 목적지를 계산하고, 응답·저장 상태·이어하기에서 시간과 장소가 일치한다.
3. 불가능한 대기나 목적지는 이유를 알리고 현재 상태를 보존한다. 이동 실패를 임의의 거점 복귀로 처리하지 않는다.
4. 극야해안 여관 뒷마당과 다른 팩의 세부 공간을 회귀로 확인한다. 실제 입력부터 다음 턴 서술·NPC 배치까지 검사한다.
