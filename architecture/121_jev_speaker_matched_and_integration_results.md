# 121 — 발화자 JEV 동일 조건 재시험과 연결 검증

2026-09-22. **모델은 유망하지만 서버만 교체하면 보류 정책이 화면에서 무효화된다.** 명시적인 화자 미확정 상태를 클라이언트까지 전달해야 한다. 이번에는 평가 코드·사례·문서만 변경했다. 게임 서버 실행, 운영 코드 수정, 커밋·푸시는 하지 않았다.

## 동일 조건 API 재시험

JEV와 nanoControl에 동일한 실명·별칭·역할, 대사 문맥(앞120/대사50/뒤40), NONE 허용 정책을 제공했다. JEV 선택지 설명도 해당 후보 정보와 동일하다. API 특성상 구조화 선택과 텍스트 출력 형식은 다르며, nano 프롬프트를 최적화한 한계 성능 비교는 아니다. 기존 정책 nano 팔도 후보 정보는 같게 제공하되 첫 후보 강제 선택과 추가 검증 호출을 유지했다.

기존 16장면과 신규 8장면, 총 24장면/27대사를 각 2회 실행했다. 두 번째에는 후보 및 사례 순서를 뒤집었다. 신규 사례에는 다른 NPC, 동일 별칭 두 명, 성별 정보 없음, 플레이어 발언, 후보 밖 인물, 15명 후보가 포함된다. 기준은 호출 전에 고정했다.

| 전체 48장면/54대사 관측 | JEV 단독 | 동일 정책 nanoControl | 기존 정책 nano+검증 |
|---|---:|---:|---:|
| 원선택 기준 일치 | 54/54 | 34/54 | 34/54 |
| 중앙 요청 지연 | 258.1ms | 776.6ms | 830.1ms |
| p95 | 347.4ms | 1,128.7ms | 1,719.9ms |
| 추가 검증 호출 | 0 | 0 | 8 |

- JEV confidence ≥ 0.9 채택 47/54, 채택된 선택 중 오류 0.
- 나머지 7개를 보류하면 분류 기준 일치 51/54. 실제 NPC 대사 3개(성별 단서 2회, 주어 전환 1회)가 미할당된다.
- 최초 검증셋 JEV 16/16, nanoControl 12/16. 신규 검증셋 JEV 18/18, nanoControl 10/18. 각 세트 절반은 같은 사례의 반복이다.
- nanoControl 형식 미준수 6대사 관측은 오답에 포함했다. 번호만 출력하거나 두 대사에 한 답만 출력한 응답을 정답을 이용해 복구하지 않았다.
- 유효 API 응답은 각 팔 48/48. 첫 샌드박스 시도는 네트워크 차단으로 모두 fetch 실패했고 별도 파일로 남아 있다. 표는 접근 승인 후 성공 실행이다.

## 서버 실제 후처리 실험

prototype 스킬의 폐기 가능한 실험 방식으로, TypeScript 로딩 시 메모리에서 Step A만 JEV-only 어댑터로 대체했다. 실제 `NarrativePostprocessService.insertDialogueMarkers`의 대사 추출 및 나머지 후처리 코드를 실행했다. 응답은 주입했으며 API/DB/전체 게임 턴은 실행하지 않았다. 운영 JEV 연결을 구현한 것과 다르다.

어댑터는 허용 후보 ID와 유한 confidence 0.9~1만 채택했다. NONE/누락/오류/timeout은 미할당 유지. 부분 채택 뒤에도 nano나 강제 regex 배정은 하지 않았다. 스트리밍은 기존 strict regex만 유지했다.

18개 서버 시나리오에서 기대한 동작을 확인했다:

- 고신뢰·부분 배정, 저신뢰 보류, 대표 NPC가 있어도 NONE 유지.
- 후보 밖 ID, 비정상 confidence, 답 누락, timeout 무배정.
- 스트리밍 명확/모호 사례, JSON 모드 모델 무호출.
- 기존 마커, 짧은 인용, 입력 반복, 후보 없음 무호출.
- 미소개 NPC는 별칭 표시.
- 지목/집중 대상과 다른 마커는 기존 규칙대로 대사 삭제.

생성 모델 호출은 모두 0이었다. 마지막 삭제 사례는 새 판단도 후속 정책과 충돌하면 삭제된다는 경계 확인이지, 삭제 정책의 적절성을 평가한 것은 아니다.

## 클라이언트 연결 차단점

실제 `NarratorContent`/`renderStyledText`를 실행해 생성되는 말풍선 속성을 확인했다. 시각적 DialogueBubble 컴포넌트만 대체했으며 브라우저 렌더링은 하지 않았다.

| 서버 출력 | 실제 말풍선 | 목표 |
|---|---|---|
| 저신뢰 마커 없이 보류 | 대표 NPC 미라 | 미확정 유지 |
| NONE, 마커 없음 | 대표 NPC 미라 | 미확정 유지 |
| 첫 줄 미라 확정, 다음 줄 낯선 사람 미할당 | 모두 미라 | 두 번째 미확정 |

원인은 `client/src/components/narrative/narrative-text.tsx`의 speakingNpc fallback이다. `markerSeenInTurn`은 함수 내부 변수인데 `NarratorContent`가 줄마다 함수를 호출하므로 다음 줄에는 false로 초기화된다. 서버의 마커 누락만으로는 보류 정책을 보존하지 못한다.

재현: speakingNpc에 미라를 지정하고 아래 텍스트를 전달하면 두 번째 대사도 미라의 이름·초상화를 상속한다.

```text
@[미라|NPC_MIRA] "통행증을 보여주고 지나가시오."
낯선 사람이 말했다. "나는 이 도시 사람이 아닙니다."
```

마커 없이 `바람이 불었다. "그 이야기는 나중에 합시다."`만 전달해도 같은 상속이 발생했다. 결과를 기록한 뒤 임시 프로토타입은 삭제했다. API 평가 하네스와 원본 데이터는 보존했다.

## 다음 구현 범위

1. 비스트리밍 발화자를 JEV 단일 요청으로 교체하며 nano 및 marker-verify를 제거한다.
2. NONE/저신뢰/실패를 단순 마커 누락과 구별하는 명시적 상태로 전달한다. 대사별 미확정 세그먼트 또는 버전 있는 배정 정책 메타데이터가 후보이며, 기존 스트리밍·과거 저장본의 fallback을 전역 삭제하지 않는다.
3. 서버 이름 정리·primary 교정이 미확정 표시를 재배정하지 않도록 하고, 화면에서 대표 NPC 이름·초상화를 상속하지 않도록 함께 검증한다. 플레이어 발언을 NPC로 바꾸지 않는다.
4. 줄바꿈·부분 배정·재접속 복원·타이핑·실명 비공개·지목/집중 정책을 회귀 검증한다. 15후보 제한의 중요 NPC 누락 문제도 별도로 처리한다.

**서버만 교체하는 배포는 권장하지 않는다.** 주사위 전체 판정은 이전 보류 결론 유지. 기존 서버 관련 테스트 6개 모음/151개 통과는 현재 코드의 제한적 회귀 확인이지 새 통합 전체 통과가 아니다.
