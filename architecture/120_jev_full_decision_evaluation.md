# 120 — JEV 완전 판단 대체 평가

2026-09-22. 평가만 수행했다. 운영 코드 수정, 로컬 게임 서버 실행, 커밋·푸시는 하지 않았다. 목표는 비용보다 속도·정확도·확장성이며, 정상 경로에 `JEV → nano 문구 생성`을 추가하지 않는 것이다.

## 결론

1. **Challenge 전체 교체는 보류.** 단일 JEV 요청은 빨랐지만 수치 축의 신뢰도가 낮다. 사전에 정한 전체 11개 질문 confidence ≥ 0.9를 검증셋에서 만족한 관측은 0/32다. 단순 FREE/CHECK만으로 전체 계약을 대체했다고 할 수 없다.
2. **비스트리밍 발화자 식별은 다음 교체 후보.** JEV 단독 선택과 저신뢰 보류가 유망하다. 다만 입력 정보가 대조군보다 풍부했던 편향이 있어 동일 입력 재시험과 후처리 통합 테스트를 먼저 해야 한다. 운영 채택 완료가 아니다.
3. NPC 반응·대사·기억·흔적 등 문구 생성은 이번 범위 밖이며 그대로 유지한다. 스트리밍 발화자 경로는 원래 모델 호출이 없으므로 JEV를 추가하지 않는다.

## 방법

- JEV: OpenRouter Decisions API, 요청 모델 `typesafe/jev-1.13`, 응답 모델 `typesafe/jev-1.13-20260917`.
- 대조군: `openai/gpt-4.1-nano`. 발화자 기존 경로는 필요시 `openai/gpt-4.1-mini` 검증 호출도 포함했다.
- Challenge 28개 합성 사례: 개발 12개, 검증 16개, 각 2회. 발화자 16개 합성 장면/18개 대사: 개발 8장면, 검증 8장면, 각 2회. 반복 관측은 독립 사례가 아니다.
- 발화자 두 번째 반복에서는 장면 처리 순서와 후보 순서를 뒤집었다.
- JEV 2초, nano 5초의 평가용 요청 제한. 일반 운영 재시도·rate limiter·전체 게임 턴은 재현하지 않았다. 실제 사이트 첫 토큰 지연을 측정한 결과가 아니다.
- 현재 TypeScript 서비스의 프롬프트·파서·정규화를 메모리에서 재사용했다. 소스 파일은 변경하지 않았다.
- 기준과 신뢰도 문턱은 실행 전에 고정했다. 결과를 보고 문턱을 낮추지 않았다.

## 1. Challenge

단일 요청에 result, statHint, difficultyMod, plausibility, physicalImpact, safety 및 사회적 인상 5축을 넣었다. 자유 문구는 생성하지 않고 서버 고정 문구로 reason을 대체했다.

| 검증셋 지표 (16사례 × 2회) | JEV 단독 | nano 전체 appraisal 대조군 |
|---|---:|---:|
| 파싱 유효 | 32/32 | 30/32 |
| 유효 응답 중앙 지연 | 253.1ms | 1,225.5ms |
| 유효 응답 p95 | 340.5ms | 1,713.6ms |
| 전체 11축 confidence ≥ 0.9 | 0/32 | 해당 없음 |
| 제한적 최종 분기 일치 | 32/32 | 27/32 |

마지막 행은 저신뢰 JEV 결과까지 사용하고 현재 세계 경계·안전성 규칙을 적용한 뒤 REFUSED/NO_GAIN/FREE/CHECK만 비교한 별도 감사다. 감정 변화·보상·흔적·아크 강제 판정·메인 서술·UI까지 통과했다는 뜻이 아니다. nano 대조군은 이미 운영에 있는 병렬 JEV result 보정을 제외했으므로 현재 사이트의 실패율로 해석하면 안 된다. nano 오류 2회는 metagame 사례의 `result=OUT_OF_SCOPE` 형식 오류이며 기존 fallback 결과를 분기 감사에 포함했다.

개발셋 중앙 지연은 JEV 246.7ms, nano 1,185.7ms였다. 전체 56관측 중 모든 축의 신뢰도 문턱을 넘은 것은 2개뿐이다. 특히 난이도와 사회적 인상 수치가 문제이며, 대략 5배 빠른 개별 요청만으로 교체를 승인할 수 없다.

### 평가 기준의 한계

- raw 전체제약 통과는 검증 JEV 19/32, nano 18/32(유효 응답만 보면 18/30)이나 대표 정확도로 쓰지 않는다. 일부 physicalImpact 정답이 인물 상해를 장소의 지속 흔적으로 취급하여 실제 계약과 모호하게 맞물린다. 원본 라벨은 사후 수정하지 않았다.
- 사회적 인상 일부 허용 범위가 -5~5로 넓다. 허용 범위 통과는 정밀한 감정 판단의 증거가 아니다.
- 안전 범주가 합성 56관측에서 기준과 맞았지만, 이는 안전성 인증이나 실제 운영 일반화 증거가 아니다.
- 고정 reason은 기만 발언·행동을 하는 척하기 등의 의미를 완전히 보존하지 않는다. [계약 검토](119_jev_full_decision_contract_review.md)의 별도 actionMeaning 선택 질문은 이번 11질문 평가에 포함하지 않았다.
- socialImpact의 null과 영벡터 객체는 실제 감정 계산에서 동등하지 않다. 경계 적용 후 불변식과 장애시 안전 정책도 통합 검증이 필요하다.

다음 단계는 의미 계약 보완 및 모호한 라벨의 독립 재검토다. 수치를 서버 규칙으로 옮기는 설계는 가능하지만 게임 밸런스 변경이므로 별도 판단 없이 도입하지 않는다. JEV 뒤에 nano를 계속 붙이는 우회 구현은 하지 않았다.

## 2. 발화자 식별

장면당 JEV 한 번으로 각 대사에 후보 ID 또는 NONE을 선택시켰다. JEV 뒤에 nano/검증 모델을 호출하지 않았다.

| 검증셋 지표 (8장면 × 2회, 16대사 관측) | JEV | 기존 nano + 필요시 검증 | NONE 허용 nano 대조군 |
|---|---:|---:|---:|
| 원선택 기준 일치 | 16/16 | 9/16 | 12/16 |
| 중앙 지연 | 239.5ms | 851.1ms | 777.5ms |
| p95 | 280.3ms | 1,811.0ms | 1,038.4ms |

개발+검증 전체에서 JEV 원선택은 36/36 일치했다. confidence ≥ 0.9인 32개 중 오배정은 없었다. 나머지 4개를 NONE으로 보류하는 가상 정책에서는 35/36 일치하며, 실제 NPC의 대사 1개를 놓친다. 이는 실제 UI 표시 정확도가 아니라 보류 정책 적용 후 분류 일치다. 기존 경로는 전체 27/36, NONE 허용 nano 대조군은 23/36이었다. 기존 경로의 추가 검증 호출은 32장면 관측 중 6회였다.

### 비교 편향과 미검증 영역

- **후보 정보가 완전히 같지 않았다.** JEV에는 실명·별칭·역할을 모두 넣었으나 nano 후보에는 기존 방식인 `alias || name`을 썼다. 실명 기반 사례의 차이를 순수 모델 성능 차이로 주장할 수 없다. NONE 허용 대조군도 이 입력 차이는 해소하지 못했다.
- 기존 프롬프트는 불확실하면 첫 NPC를 강제 선택한다. NONE 허용에 따른 정책 개선과 모델 개선을 분리해야 한다.
- 모든 장면이 같은 NPC 3명을 사용하며 성별 단서도 비교적 명확했다. 새로운 이름·별칭 충돌·15후보 한도·후보 누락은 아직 평가하지 않았다.
- 대사 앞120자/대사50자/뒤40자를 사용했지만 실제 DB 별칭 탐색·regex 백필·마커 정리·미소개 이름 가리기·부분 배정·후속 UI는 전체 실행하지 않았다.
- 최초 nanoControl 파서는 번호 없는 정상 ID 응답을 누락했다. 정확한 줄 수와 후보 ID/NONE 검증을 유지하면서 파서를 고쳐 **추가 API 호출 없이 재채점**했다. 원본과 수정 보고서를 모두 보존했다. 수정 후에도 개발셋 4개 대사 관측은 응답 형식 불일치로 미파싱이다.

권장 다음 순서: 후보 정보와 NONE 정책을 통일한 재시험 → 실제 후처리 통합 테스트 → 통과시 비스트리밍 nano 및 marker-verify를 JEV 단독으로 교체. 저신뢰는 안전하게 미할당 유지하고 스트리밍에는 모델 호출을 추가하지 않는다.
