# 140. 구조화(JSON) 스트리밍 가능성 조사

> 상태: 운영 전면 적용(2026-10-12) — 플래그 제거, 서술은 JSON 스키마 응답만. 화자 추측 후처리는 구조화 귀속 턴에서 생략(§후처리 걷어내기). 참고: [[architecture/35_llm_streaming|llm streaming]], `../dimtale/playtest-reports/2026-09-30_stream_scene_results.md`

## 결론

**가능하다.** "JSON 모드는 스트리밍과 비호환"(arch/35, 불변식 37, arch/104 §P2-4)은 출력 형식의 한계가 아니었다. **부분 JSON 파서가 없었다**는 구현 사정이었다(archive/37: "향후 Partial JSON 파서 도입 시 재검토 필요"). JSON 은 출력 구조이고 스트리밍은 수신 방식이라, 둘은 함께 쓸 수 있다. OpenRouter 문서도 `response_format: json_schema` 와 `stream: true` 의 동시 사용을 지원한다. 다만 지원 여부는 모델이 아니라 엔드포인트 단위다.

## 현재 Graymar

- 메인 서술은 텍스트 스트리밍이다. 모델은 `별칭: "대사"` 콜론 라벨로 쓰고, `StreamClassifier` 가 문장 단위로 끊어 `narration`/`dialogue` SSE 이벤트(`{type, text, npcName?, npcImage?}`)를 보낸다. 마커·화자 귀속은 휴리스틱과 후처리 체인이 맡는다: `insertDialogueMarkers`, 무마커 대사 JEV, Step F, 화자 연속 귀속, R7 마스킹, R5v2.
- 스트리밍된 텍스트는 **임시본**이다. `done` 이벤트의 최종 서술로 교체된다(StoryBlock onComplete).
- 구 JSON 모드(`LLM_JSON_MODE`)는 스키마 없는 `json_object` 일괄 파싱이었다. 지금 켜면 JSON 원문 조각이 분류기로 흘러가 문자열이 대사로 오인된다. 현재는 사문 경로다.
- 부수 효과: 비스트리밍 블록 안에 있던 THREAD 생성도 함께 사문화됐다(arch/139 §7.2).

## 실측 (GPT-6 Luna·추론 none·실제 13K자 프롬프트, run 159d5b40 T6, 각 4회)

| | 텍스트 스트리밍(현행) | JSON 스키마 스트리밍 |
|---|---|---|
| 정상 종료·유효 JSON | 4/4 | 4/4 |
| 첫 토큰 | 1.28~1.31초 | 1.39~1.48초 |
| 첫 본문 표시 가능 | — | 1.60~1.66초 |
| 전체 완료 | 4.6~5.2초 | 5.1~5.6초 |
| 비용 | 기준 | 약 +15% (키 문자열 출력) |
| 대사 화자 ID 정확 | 콜론 라벨 → 서버 추정 | 8/9 (89%) |
| 군중 대사 | 서술 속 따옴표 — 화자 없음 | `UNKNOWN` + 호칭으로 분리 |

틀린 1건은 회계사 대사에 `speaker_id: UNKNOWN` 을 넣은 경우다. 이때도 `speaker` 필드에는 실제 별칭이 맞게 들어 있었다. 서버가 로스터 별칭으로 대조하면 결정론적으로 교정할 수 있다. 턴마다 `speaker_id` enum 을 로스터 ID + UNKNOWN 으로 묶는 방법도 있다.

Dimtale 의 선행 검증(2026-09-30, GPT-5.6 Luna high, 24회)도 같은 결론이다. 화자 귀속 12/12였고, 스트리밍 중 표시 텍스트는 매 갱신이 최종 본문의 정확한 접두사였다. 즉 **임시본 = 최종본**이 성립했다.

## 도입하면 바뀌는 것

- **화자 귀속이 구조가 된다.** 마커 후처리 체인(콜론 라벨 파싱, 무마커 대사 재귀속, Step F, 화자 연속 귀속, MarkerCollision)의 상당 부분이 필요 없어진다. arch/114 기준 후처리 서비스만 2,291줄이다.
- **클라이언트 변경이 작다.** 지금 SSE 이벤트가 이미 `narration`/`dialogue` + `npcName` 이다. 서버가 JSON 조각을 같은 이벤트로 변환하면 클라이언트는 거의 그대로 쓸 수 있다.
- **임시본과 최종본의 차이가 줄어든다.** R7 마스킹과 R5v2 를 조각 단위로 먼저 적용하면, 표시한 텍스트가 곧 저장 텍스트가 될 수 있다.
- **같은 호출에 짧은 필드를 덧붙일 수 있다.** 예: `thread` 요약을 넣으면 사문화된 THREAD 를 추가 호출 없이 되살릴 수 있다. 서술 뒤에 오는 필드라 표시 지연은 없지만 출력 토큰은 는다.

## 비용과 위험

- 서버에 증분 JSON 파서가 필요하다. Dimtale `stream.py` 의 `Partial`(약 60줄)이 참고 구현이며, 이스케이프·서로게이트 경계 처리가 포함돼 있다.
- 시스템 프롬프트의 출력 형식 지시(콜론 라벨·마커 규칙)를 바꿔야 한다. 골든 스냅샷과 V8·V10 게이트가 함께 움직인다.
- 모델 이식성: 엔드포인트가 `structured_outputs` 를 지원해야 한다. GPT-6 Luna(OpenAI)는 지원하고, 다른 후보는 공급자별로 확인해야 한다. 텍스트 경로는 폴백으로 남긴다.
- arch/77 P4.0 금지선(스트림 emit 순서·sanitize 시점)을 건드리는 변경이다. 플래그 뒤 격리가 필요하다.
- 첫 표시가 약 0.3초 늦다(키 문자열 + 화자 필드가 본문보다 먼저 와야 함).

## 검증 순서 제안

1. 오프라인 재생 확대 — 실프롬프트 30턴 이상 × 두 방식. 화자 정확도, 어체 위반, 분량, 첫 표시, 비용을 비교한다.
2. 플래그(`LLM_STRUCTURED_STREAM`) 뒤 서버 어댑터 — JSON 조각을 기존 SSE 이벤트로 변환한다. 후처리 체인은 유지하고 결과를 대조한다.
3. 대조에서 차이가 없는 후처리 단계부터 제거한다.

## 구현 (2026-10-12, 플래그 `LLM_STRUCTURED_STREAM`, 기본 OFF)

- `server/src/llm/structured-narrative-stream.core.ts` (+스펙 14): 증분 JSON 파서(Dimtale `Partial` 이식 — 이스케이프·`\u`·서로게이트 경계 보류)와 `StructuredNarrativeStream`. 화자 필드가 완성된 조각만 내보낸다. 서술은 문장 단위, 대사는 조각이 완성될 때 한 번. 이미 내보낸 텍스트가 이후 파싱 결과의 접두사가 아니면 예외. 완료 시 마커 형식 정본(`@[표시명|NPC_ID] "대사"`)으로 바꿔 기존 후처리 체인에 넘긴다.
- 화자 ID 가 후보에 없으면 표시명·이름 정확 일치로 교정한다. 후보는 **팩 전체 NPC** — 아직 만나지 않은 NPC도 ID·초상화를 받는다. 미소개 NPC 의 표시명은 별칭이라 실명이 노출되지 않는다.
- 공급자 `jsonSchema` 요청 필드 → `response_format: json_schema`. 워커 스트리밍 루프에서 플래그가 켜지면 분류기 대신 변환기를 쓴다. 증분 파싱 실패·최종 검증 실패 시 텍스트 요청으로 non-stream 폴백한다.
- R7 마스킹·R5v2 는 기존 `sanitizeStreamSegment` 를 그대로 거친다. SSE 이벤트 형식이 같아 **클라이언트 변경은 0**이다. 런타임 플래그라 어드민에서 재시작 없이 켜고 끌 수 있다.

## 격리 실측 (스키마 복제 DB `graymar_structured_eval_20261012` + 3015 서버, GPT-6 Luna)

**실클라 SSE 비교** (그레이마르, 같은 행동 대본 10턴씩, 새 계정·새 런)

| | OFF(텍스트) | ON(JSON) |
|---|---|---|
| 스트리밍 표시 ↔ 최종 저장본 일치도 | 9/10 ≥0.999 | 8/10 = 1.000, 나머지 0.946·0.993 |
| 턴당 SSE 조각 수 | 4~8 | 7~12 (서술 문장 단위라 더 잘게) |
| 서술 호출 평균 / 중앙값 | 3.75초 / 3.83초 | 4.64초 / 4.83초 |
| 호출당 비용 / 출력 토큰 | 1.16원 / 267 | 1.27원(+9%) / 356(+33%) |
| 대사 마커 중 NPC ID 포함 / 무명 | 13/13 / 0 | 12/12 / 0 |
| 실패·폴백 | 0 | 0 |

턴 제출부터 첫 표시까지는 서버 사전 처리(판정·nano)가 7~17초 편차로 섞여 두 방식을 비교할 수 없었다. LLM 단독 재생(§실측)에서 첫 본문 표시 차이는 +0.3초다.

**정본 게이트**: ON 상태 그레이마르 10턴 15/15, 별빛모래 10턴 15/15 × 2런(V8·V10 화자 정합 포함). 시험 서버의 구조화 스트림 처리 턴은 총 61개, 증분 파싱 실패·텍스트 폴백 0건.

**관찰**
- GPT-6 Luna 는 현행 텍스트 방식에서도 라벨을 잘 지켜, 이번 표본에서는 화자 귀속 차이가 드러나지 않았다. 구조화의 이점(화자 구조 지정·군중 대사 분리)은 라벨 준수가 약한 모델에서 크다(Solar 라벨 57~82%, GLM 66~76% — arch/25·113).
- 별빛모래 BACKGROUND NPC '부적 상인'은 ON·운영(OFF) 모두 `@[부적 상인]` 처럼 ID 없이 저장된다. 기존 후처리 규칙에 따른 것으로 보이며 이번 변경과 무관하다.
- ON 의 추가 지연·비용(+0.9초·+9%)은 JSON 키 문자열 출력 때문이다. 스키마 키를 짧게 하면 줄일 수 있다(예: `t`/`id`/`who`/`text`).

## 다음 단계 후보

1. 운영 일부 적용 전, 라벨이 약한 모델(Solar 등)에서 같은 비교를 한다 — 구조화의 실익이 가장 큰 조건이다.
2. 스키마에 `thread` 요약 필드를 추가해 사문화된 THREAD 를 되살린다(arch/139 §7.2).
3. ON 이 기본이 되면 마커 추정 후처리(무마커 대사 재귀속·Step F·화자 연속 귀속)를 대조 후 단계적으로 걷어낸다.

## 운영 전환과 후처리 걷어내기 (2026-10-12, 소유자 결정)

**플래그 제거 — JSON 전용.** `LLM_STRUCTURED_STREAM` 을 없앴다. 서술 스트리밍은 항상 JSON 스키마로 요청한다. 실패 시 순서는 다음과 같다: 같은 스키마로 non-stream 재호출 → 같은 변환기(`structuredJsonToMarkerText`)로 정본화 → 그마저 파싱 불가면 텍스트 요청. 구 텍스트 분류기 `StreamClassifierService`(478줄)와 그 스펙, 텍스트 전용 `NarrativeStreamPrefixGate` 는 삭제했다. 후보 생성·이벤트 타입만 `speaker-candidates.core.ts` 로 옮겼다. caller 형태 구제는 JSON 스키마 요청에서 끈다.

**구조화 귀속(`structuredAttribution`).** `stageGenerate` 가 JSON 변환 원본을 기억한다. 이후 재시도·구제·아크 재작성·증거 정합 교체로 서술이 바뀌지 않았을 때만 참이다(품질 필터 직전 비교). 참인 턴은 아래를 건너뛴다.

| 생략 | 이유 |
|---|---|
| 따옴표 복구, Step A(무마커 대사 regex 백필 + JEV 화자 판정) | 대사는 이미 마커. 서술 속 인용구를 대사로 오인 |
| B-2.5 이름 재추측 | 느슨한 이름 일치로 NPC ID 를 바꾸거나 모르는 라벨을 팩 NPC 에 연결 |
| F-0 지목 대상 외 대사 삭제, F-aux 보조 화자 삭제·재배정, Step F 불일치 교체 | 끼어든 NPC 대사를 지우거나 주 화자로 덮어씀(서술 속 이름까지 치환) |
| 마커 겹침 복구, NestedMarkerUnwrap·MultiQuoteSplit, BareDialogue | 정본 마커에 무의미하거나 서술 문단을 대사로 바꿈 |

**대체:** 마커 ID 로만 표시명을 정본화하고(초상화 없는 NPC 는 라벨만 — B-1 규칙과 동일), 등장 NPC(appearedNpcIds)를 채운다. **유지:** 실명 세이프가드(C), 도입문 정리(D), 따옴표 내 접두 제거(E), 자기소개 처리, R5v2 어체 교정, 누출·쓰레기 토큰 정리. 변환기는 서술 조각 속 큰따옴표를 작은따옴표로 바꾼다 — 대사의 정본은 dialogue 조각뿐이다.

**검증:** 전체 jest 3,218 통과·스냅샷 17 불변(삭제한 분류기 스펙만큼 감소). 운영 재시작 후 스모크 PASS. 형식 확인 플레이테스트 6턴 × 2팩에서 그레이마르 14/15, 별빛모래 13/15 였다. 실패한 V2·V5 는 짧은 런의 구조적 한계다 — 장소를 떠나지 않아 방문 기록 0, 별빛모래는 4턴 동안 조우 NPC 1명. 조우 횟수는 턴 처리 단계에서 오르므로 이번 변경과 무관하다. 운영 로그로는 18턴 전부 JSON 스트림, 폴백 0, NpcMismatch·FocusedAuxStrip·BareDialogue·따옴표 복구·마커 겹침 발동 0, JEV 마커 화자 호출 0 을 확인했다.

**남은 일:** 잠금 중 극적 등장 인계(`protectedEntryNpcId`)는 Step F 와 함께 생략됐다 — 구조화 턴에서 ID 기반으로 다시 세울지 결정이 필요하다. `reconcileSpeakingNpcAndPortrait`·R5v2 의 화자 해석은 아직 이름 우선이다(라벨이 정본 표시명이라 실제 피해는 낮음). 텍스트 폴백 경로의 화자 추측 코드는 폴백 빈도를 보고 삭제를 판단한다.

## 커밋 전 리뷰 후속 (2026-10-12, gstack `/review`)

전문 리뷰(전문 리뷰어 5 + 레드팀 + 적대적 검토 3회)에서 나온 결함을 고쳤다. 모두 회귀 테스트로 고정했다.

- **모델 화자 필드 신뢰 경계** — 매칭 안 된 `speaker` 라벨이 SSE `npcName` 으로 그대로 나가 미소개 실명이 새고(스모크 실측), 라벨에 `|NPC_X` 를 넣으면 마커 ID 가 위조됐다. 라벨에서 마커 기호·줄바꿈·비한글 라벨을 걷어내고, `sanitizeStreamSegment` 가 `npcName` 에도 실명 가리기를 적용한다. 구조화 턴의 ID 없는 라벨 마커는 B-2.5(실명·별칭·aliases 정확 일치만)로 별칭 해석한다.
- **장면 게이트** — 화자 후보가 팩 전체라 장면에 없는 CORE NPC 가 "건너편 목소리"로 ID 를 얻고 초상화·등장 기록·LockSeed 까지 이어졌다(당일 실런 89마커 중 1건, 진양성). 장면 NPC(`collectStructuredSceneNpcIds` — ui 장면 집합 + 런 상태 현장 presentNpcs, 도착 턴 대비)의 ID 만 믿고 장면 밖은 표시명 라벨만 남긴다. 장면 밖 ID 는 `reconcileSpeakingNpcAndPortrait` 까지 넘겨 표시명 역해석으로 되살아나지 않게 하고, 라이브 스트림도 같은 판정으로 초상화를 뺀다.
- **폴백 사다리** — 같은 스키마 non-stream 호출이 실패해도 텍스트 요청 1회로 복구한다(`callStructuredNonStream`, 구 동작의 텍스트 복구 보존).
- **스트림 정체 이중 과금** — 토큰이 온 뒤 스트림이 멈추면 `callStream` 의 내부 non-stream 폴백 응답이 부분 JSON 뒤에 붙어 파서가 거부하고 워커가 또 사서 같은 서술을 두세 번 과금했다. JSON 스키마 요청은 내부 폴백 없이 예외를 올려 워커 사다리가 1회만 사게 했다. 소비자가 스트림을 중간에 버리면 upstream 요청을 abort 한다(종전엔 max_tokens 까지 계속 생성·과금, usage 미기록).
- **플레이어 발화** — 라벨이 플레이어 호칭(당신·용병 등)이나 캐릭터 이름이면 NPC 말풍선이 아니라 서술로 돌린다(구 분류기의 arch/91 배제 이식).
- 기타: 대사 안 줄바꿈 합치기, 스트림 서술 따옴표를 저장본과 일치, 스키마 밖 type 미송출, 파서 프로토타입 키, 중간 요약 창 상수(`MID_SUMMARY_RECENT_WINDOW`)로 prewarm 예측 고정, 사문이 된 `decideSoleSpeakerContinuityCore` 삭제.

남긴 것(소유자 Skip): 실제로 보낸 요청·원본 JSON·폴백 경로 기록, `LLM_JSON_MODE` 사문 경로 제거, `response_format` 중복 코드. 증분 파서의 전체 재파싱은 2,048토큰 상한에서 턴당 수 ms 라 그대로 둔다.
