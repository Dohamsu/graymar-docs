# 118. NPC 반응·거절 JEV 분리 실측 — 2026-09-22

## 결정

**JEV의 두 필드 분류는 유망하지만, `JEV → nano 표현 생성` 직렬 분리는 지금 운영에 도입하지 않는다.** 합성 평가에서 분류 정답률과 반복 일관성은 좋았으나, 실제 직렬 실행은 기존 반응 디렉터보다 느렸다. 빠른 분류기를 추가하는 것과 사용자에게 첫 서술이 빨리 보이는 것은 다른 문제다.

운영 코드·설정·DB를 변경하지 않았고 게임 서버를 시작하지 않았다. API 비교 평가만 실행했다. 커밋·푸시는 하지 않았다.

## 1. 재현 자료와 범위

- [평가 스크립트](../scripts/jev-npc-eval.mjs), [사전 작성 사례](../scripts/jev-npc-cases.mjs)
- [본 비교 원시 결과](../playtest-reports/jev_npc_2026-09-22T01-31-58-781Z.json)
- [실제 직렬 실행 원시 결과](../playtest-reports/jev_npc_2026-09-22T01-34-59-574Z.json)
- [호출 구조·전환 설계](117_npc_jev_split_design.md)

32개 합성 사례(개발 16 + 미공개 문구 검증 16)를 각 2회 실행했다. 64번의 판단 관측이며 **64개 독립 사례가 아니다**. 검증 16개도 개발 세트와 같은 상황군을 공유하는 인물/문구 변형이라, 도메인 외 일반화 검증으로 볼 수 없다. 정답은 모델 합의가 아닌 작성자가 사전에 정한 허용 반응·거절 집합이며 사람 검수된 운영 정답은 아니다.

인사·감사·비밀 질문·반복 거절·위협·사과·위험 행동 목격·침묵·목적 확인·은인·기만·부정문·지시 주입·바쁜 NPC·반응 정체·친구를 포함했다. 합성 맥락은 의도가 비교적 명확하며 실제 감정 수치·자기 활동·복잡한 관계 상태가 충분하지 않다. 사례별 허용 집합의 조합 일치율을 측정하므로 정답 정의에 주관성이 남는다.

기존 서비스의 **현행 소스**에서 프롬프트, 맥락 조립, JSON 파서, 반복 방지 R2, 디렉터 내부 최대 2회 재시도·기본값 복귀를 재사용했다. 실제 LlmCaller의 provider 재시도·대체 provider·rate limiter는 제외했다. 모델은 `openai/gpt-4.1-nano`, JEV 응답 버전은 `typesafe/jev-1.13-20260917`. nano는 기존 maxTokens=250 및 temperature=0.7/0.4, 5초/시도; JEV는 2초 제한이다. 실제 사이트 런타임 설정을 조회한 것은 아니다.

JEV에는 같은 맥락과 기존 반응 정책을 주되 자유문장 생성 지시는 제거하고 두 choice를 요청했다. **JEV는 두 필드, 기존 nano는 전체 반응 객체를 생성하므로 시간 차이는 동일 작업량의 모델 성능비가 아니다.** 기대 정답은 두 모델 입력 모두에 포함하지 않았다. 임계값 0.9는 실행 전 고정했고 검증 결과를 보고 낮추지 않았다.

첫 인증 실패 실행(`01-30-53-548Z`)은 무효로 표시했으며 아래 수치에서 전부 제외했다. 평가 스크립트에는 인증 실패 즉시 중단을 추가했다.

## 2. 미공개 문구 검증 결과

검증 사례 16개 × 2회 = 32개 관측. 이 세트에서는 두 모델 모두 정상 결과가 있어 같은 분모로 비교할 수 있다.

| 지표 | JEV | 기존 nano 디렉터 |
|---|---:|---:|
| 반응 종류 허용 집합 일치 | 32/32 (100%) | 26/32 (81.25%) |
| 거절 강도 허용 집합 일치 | 30/32 (93.75%) | 27/32 (84.38%) |
| 두 필드 동시 일치 | **30/32 (93.75%)** | **21/32 (65.63%)** |
| 호출 경로 p50 | 247ms | 1,562ms |
| 호출 경로 p95 | 319ms | 2,632ms |
| 결과 기본값 복귀 | 0 | 0 |

개발 세트 JEV는 30/32 동시 일치. nano는 정상 30개 중 18개 일치, 기본값 복귀 2개까지 포함한 최종 전달 결과는 19/32 일치였다. **기본값 복귀를 모델 정답으로 계산하지 않았다.** 전체 32개 사례의 두 번 실행에서 JEV의 선택 쌍은 32/32 동일했고 nano는 23/32 동일했다(기본값 복귀 포함 사례는 안정성 성공으로 세지 않음). nano의 비결정적 temperature도 이 차이에 영향을 준다.

JEV의 실패는 두 세트 모두 평범한 방문 목적 확인에서 `NONE` 대신 `POLITE`를 고르는 같은 유형이었다. 해당 결과의 두 필드 최소 confidence는 약 0.54~0.61로 0.9 게이트에서 모두 보류된다.

### 신뢰도 게이트

- 검증 세트 채택: **8/32 (25%)**, 채택 결과는 **8/8 일치**.
- 실제로는 위협·사과·목격·지시 주입의 **4개 고유 사례를 두 번** 관측한 값이다. 운영 정확도 100%의 근거가 아니다.
- 나머지 75%는 대부분 틀려서가 아니라, 자연스러운 선택지가 여럿이어서 confidence가 낮다. 이 구간을 무조건 기존 nano로 직렬 복귀시키면 JEV 시간이 추가된다.
- 기준은 두 confidence의 최소값 ≥0.9 + 협조/거절 모순 없음이다. 이번 JEV 결과에는 R2로 값이 바뀐 경우가 없었다. 향후 가드가 값을 변경하면 원래 confidence를 최종 값의 confidence로 간주하면 안 된다.
- 개발 nano 결과에는 `OPEN_UP + POLITE` 모순 1건이 있었다. 거절 이력과 정합성 규칙을 모델 프롬프트에만 맡기지 않는 설계가 필요하다.

## 3. 실제 직렬 분리 속도

높은 신뢰도로 채택된 검증 사례 4개에서 **JEV를 새로 호출하고 그 결과를 nano에 전달하는 연속 실행**을 각 3회 수행했다. 동시에 동일 사례의 기존 디렉터를 호출했다. 두 enum을 다시 출력하지 않도록 표현 프롬프트를 줄였다. 12개 관측 모두 최초 API 시작부터 종료까지 wall clock을 측정했다.

| 반응 경로 지표 | 기존 nano | JEV → 축소 nano |
|---|---:|---:|
| p50 | **1,635ms** | **2,054ms** |
| p95 | **2,911ms** | **5,028ms** |
| 기존보다 빠른 사례 | — | 2/12 |
| 처리 상태 | 1/12 기존 기본값 복귀 | 11/12 필수 필드 완성, 1/12 표현 생성 실패 |

분리안은 p50 약 **26%**, p95 약 **73%** 느렸다. 꼬리 지연에는 표현 생성의 JSON 실패·재시도와 5초 timeout 1회가 포함된다. 작은 표본이므로 일반적인 비율로 확정하지는 않지만, 이 설계의 속도 개선을 주장할 근거는 없다.

분리안은 빈 객체를 기본값으로 채운 것을 완성으로 세지 않도록 필수 자유문장·감정 필드를 확인했다. 기존 경로는 현행 parser/fallback 기준을 그대로 사용하므로 두 열의 '완성' 조건이 완전히 동일하지 않다. 성공 여부 외에 실제 출력도 남겼다. JSON 완성은 표현 품질 통과를 뜻하지 않는다. 수동 확인에서 구체 몸짓 금지 위반과 판에 박힌 경계 표현이 남았고, 표현·감정 전체의 독립 정답 평가는 하지 않았다.

본 비교 원시 파일에 있는 초기 4개 writerProbe는 이전 JEV 시간과 나중 writer 시간을 합산한 탐색치다. **이 표는 이를 쓰지 않고 두 번째 원시 파일의 12개 실제 연속 실행만 사용한다.**

실제 게임의 이벤트 디렉터·프롬프트 조립·메인 모델 첫 토큰까지는 실행하지 않았다. 따라서 위 수치는 NPC 반응 경로 시간이지 첫 서술 표시 시간(TTFT)이 아니다. 기존에도 NPC가 사전 확정되면 이벤트 디렉터와 병렬이며, 이벤트 쪽이 병목이면 반응 단축이 체감으로 이어지지 않는다.

## 4. 채택 기준과 다음 설계

현재 판정: **분류 후보로 유지, 운영 편입은 보류.**

1. 두 enum은 `ReactionDecision` 계약으로 묶고, 후보·금지 조합·검증 규칙을 모델과 분리한다. 판단 단위로 버전·출처·보류 이유를 기록한다.
2. NPC별 이전 거절 강도를 명시 입력으로 추가하는 설계를 먼저 확정한다. 현재는 거절 단조성을 요구하면서도 그 전 상태 필드가 없다.
3. 자유문장 표현을 메인 서술이 직접 담당하게 하는 대안을 평가한다. JEV 뒤에 또 다른 선행 표현 호출을 넣는 구조는 속도 목표와 맞지 않았다.
4. 단, nano가 함께 내던 감정 5축·관계 신호는 실제 상태 변경에 쓰이므로 삭제하거나 사후로 미루지 않는다. 해당 상태 힌트의 책임·타이밍을 별도로 설계해야 한다. 이는 이번 두 필드 실험을 넘어서는 후속 작업이다.
5. 운영 로그를 최소화·비식별화한 독립 사례와 사람 검수를 추가한다. 임계값 조정 세트와 최종 평가 세트는 **상황군 단위로 분리**한다. 채택 부분 오류율과 커버리지를 함께 본다.
6. 첫 서술 p50 개선, p95 5% 이내 비열화, 중요한 정합성 위반 0건을 최종 gate로 제안한다. 이번 오프라인 실험은 이 전체 gate를 통과하지 않았다.

재현:

```sh
node scripts/jev-npc-eval.mjs --validate
node scripts/jev-npc-eval.mjs
node scripts/jev-npc-eval.mjs --probe-only playtest-reports/<본-비교-결과>.json
```

`--validate`는 네트워크·자격증명 없이 사례, 현행 enum, 파서, 모순 검사, 기본값 복귀의 통계 분리를 검사한다. 실제 평가는 설정된 OpenRouter 인증을 사용하며 원시 파일에는 합성 입력과 모델 응답만 저장한다.
