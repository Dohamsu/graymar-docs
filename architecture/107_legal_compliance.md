## 3. 문서 내용의 근거 — 코드 실측

방침을 추정으로 쓰면 허위기재가 되므로 전 항목을 코드·DB 에서 확인했다.

| 고지 항목 | 실측 근거 |
|-----------|-----------|
| 수집 항목 | `users` 테이블 = email·password_hash·nickname·member_no |
| 비밀번호 처리 | `auth.service.ts` bcrypt 단방향 |
| 플레이 기록 | `turns.raw_input`(이용자 입력)·`llm_output`(생성 서술) |
| 오류 신고 | `bug_reports` = description·recent_turns·client_snapshot·network_log·ui_debug_log |
| 쿠키 | `document.cookie` 사용 0건 — **쿠키 미사용**으로 기재 |
| 브라우저 저장소 | localStorage 5종 (`graymar_auth_token`·fontSize·textSpeed·last_character·pwa-install-dismissed) |
| 국외 이전 | OpenRouter(미국, 하위 Friendli·Venice·Novita·CoreWeave)·Vercel·Cloudflare |
| 접근 통제 | `users.role` + AdminGuard, `admin_audit_logs` |

### 국외 이전이 이 서비스의 핵심 고지다
`turns.raw_input`(이용자 자유 입력 최대 400자)이 LLM 프롬프트에 담겨 국외로 전송된다.
계정 정보(이메일·비밀번호)는 이전 대상이 **아니다**. 다만 이용자가 입력란에 실명·연락처를
직접 적으면 그대로 이전되므로, 방침과 가입 동의 문구 양쪽에 **입력하지 말라고 명시**했다.

## 5. ✅ 회원 탈퇴 기능 (2026-08-31 구현)

개인정보보호법상 정보주체는 삭제 요구·동의 철회권을 갖는다. 구현:

- **`POST /v1/auth/withdraw`** — JWT + **비밀번호 재확인** (토큰 탈취·방치 세션만으로
  파기되는 것 방지), 로그인과 동일 Throttle(분당 5회, 브루트포스 축). 성공 시 인증
  쿠키 삭제. admin 계정은 셀프 탈퇴 차단 (어드민 삭제 경로와 동일 보호).
- **파기 범위 = 어드민 강제 삭제와 동일 cascade** — 정본을
  `common/user-deletion.service.ts` 로 추출해 `deleteUser`(어드민)와 공유.
  삭제 정책이 두 벌로 갈라지면 파기 불일치가 생기므로 단일 정본. FK 역위상
  순서 트랜잭션 (run 자식 14테이블 → 파티 자식 → 런 → 포인트 원장 → 유저).
- **포인트 원장 전량 삭제의 근거**: 전자상거래법 5년 보존은 "대금 결제" 기록
  대상인데 현재 PG 미연동이라 유상 거래가 존재하지 않는다 (무상 가입 보너스·
  충전 코드뿐). **PG 연동 시 이 경로를 재설계해야 한다** — 유상 결제 원장은
  전량 삭제가 아니라 식별정보 분리 보관 (§6 체크리스트에 유지).
- **클라 진입점**: 설정 모달 내 계정 카드 → "회원 탈퇴" (2단 확인 — 접힘 →
  경고 + 비밀번호 입력 → 영구 삭제). 성공 시 로컬 인증·캐릭터 캐시 정리 후 랜딩.
- 방침 제3조 Callout 을 "준비 중" → 실제 동선 안내로 갱신 (약관 제12조는 기존
  기술이 이미 정합). 탈퇴 로그에 이메일은 남기지 않는다 (memberNo·id 만).
- 검증: 단위 4케이스(비밀번호 게이트·admin 차단·cascade 위임) + E2E (가입→런
  생성→오답 400→탈퇴 200→재로그인 401→DB 잔존 행 0·고아 turns 0).

§4·§8 의 판단 근거. 국내 AI 서사 서비스가 실제로 무엇을 갖추고 무엇을 안 갖췄는지 조사했다.

| 서비스 | 운영사 | 구조 | 분류/등급 | 사업자 | 통신판매업 | 게임물 등급분류 |
|--------|--------|------|-----------|--------|-----------|----------------|

**패턴**: 사업자등록·통신판매업 신고·법적 고지는 다 갖추고, **게임 카테고리와 등급분류는
아무도 안 한다.** "엔터테인먼트 카테고리 + 자체 콘텐츠 심의 규정"이 이 판의 de facto 표준.
스토어는 카테고리를 사업자가 고르고 게임위 검토는 신고 기반이라 성립하는 구조다.

**GPTRPG 가 우리와 가장 가깝다** — 주사위 판정이 있는 AI 텍스트 RPG 인데도 이 노선이고,
자체 심의 규정을 공개해 등급 상한(15세)과 금지 5분류를 선언하는 방식으로 리스크를 낮춘다.
구현은 오히려 우리가 앞설 수 있다: 저쪽은 심의 절차를 밝히지 않았고, 우리는
`content-safety.core`(arch/106)가 서버 코어에 들어가 있다. 없는 것은 **공개 문서뿐**(§9-⑤).

**게임위 입장 (2026-08-14 보도)**: "AI 와 대화하는 기능만으로 게임물이라 보기 어렵다.
다만 **유료 재화 + 확률 + 획득·손실** 구조가 콘텐츠로 구현돼 있으면 게임물에 해당할 가능성."
— dimtale 은 포인트(5p/턴)·1d6 판정·골드/HP/아이템으로 **세 요소를 모두 갖췄다.** 캐릭터챗
보다 게임성이 명확해, 기준이 정립되면 먼저 걸리는 쪽이다.

⚠️ **검증 한계**: 위 "게임물 등급분류 없음"은 **서비스가 공개 표시하지 않았다**는 뜻이지
DB 로 확인한 것이 아니다. GRAC 등급분류 DB 는 ASP.NET postback 이라 자동 조회에 실패했고
(대조군·전체조회까지 빈 결과 = 검색 미동작), 그 결과는 근거로 쓰지 않았다.
**게임제작업 등록 여부는 네 서비스 모두 확인 불가** — 공개 표시 의무가 없다.

## 8. 비공개 테스트 전환 (2026-08-20)

§4 의 행정 절차가 끝나기 전까지 **가입**을 좁힌다(노출이 아니라 — §8 색인 절 참조).
근거는 제21조의 기준이 배포 인원이 아니라 **"유통 또는 이용에 제공할 목적"**이라는 점이다.
전환 전 dimtale.com 은 색인 허용·sitemap·서치콘솔/네이버 인증·무인증 공개 통계에 더해
**가입이 완전 자유**였다 — "지인 배포"라는 자기 인식과 실제 배포 상태가 어긋나 있었고,
어긋난 지점은 홍보 경로가 아니라 **누구나 바로 플레이할 수 있다는 사실**이었다.

### 검증 스크립트 배선
가입을 시도하는 스크립트가 **9곳**이라, 게이트를 켜면 전부 400 으로 막힌다. 서버에
"테스터 도메인은 예외" 같은 구멍을 두면 게이트 자체가 무의미해지므로, 대신 스크립트가
로컬 `ADMIN_TOKEN` 으로 1회용 코드를 발급받는다.

- Python 정본 `scripts/invite_util.py` — `add_invite_code(body, BASE, note)`.
  스크립트마다 `api()` 시그니처가 제각각이라(반환이 dict / (status, dict) / None)
  각자의 api 를 쓰지 않고 `requests` 로 직접 호출한다.
- 배선 완료: `playtest` · `speedrun` · `multi_npc_play` · `model_compare` ·
  `bench-models` · `inspect-streaming-leaks` · `party-test` · `party-playtest`
- TS 정본: `e2e/_helpers.ts` `ApiClient.mintInviteCode()` (smoke/full/perf/regression 공유)
- **`_e2e-legacy/` 2건은 배선하지 않았다** — 명시적 레거시(26개 → 4개 정본 통합)라
  되살릴 때 `inviteCode` 를 직접 넣는다. `scripts/e2e/README.md` 에 명시.

### 스모크가 게이트를 검증한다
우회만 하고 넘어가면 **"비공개 테스트가 조용히 풀린" 상태를 아무도 못 잡는다** — 스모크가
담당하는 기동 시점 결함(env 오타·마이그레이션 불일치)이 정확히 이 부류다(arch/101 이
반복 지적한 "조용히 꺼진" 결함군). `smoke.ts` 는 계약을 직접 찌른다:

- 게이트 ON → **코드 없는 가입이 반드시 거절**돼야 한다. 통과하면 스모크 실패
- 게이트 OFF → 실패시키지 않되 경고 (의도적으로 껐을 수 있음)

- **fail-closed**: `INVITE_CODE_REQUIRED` 는 `false` 를 **명시해야만** 게이트가 열린다.
  env 누락이 게이트를 여는 쪽으로 기울면 안 된다 (인증 우회 fail-open 회귀와 같은 부류,
  server `0df1f1a`). 클라의 상태 조회 실패도 동일하게 "필요함"으로 처리한다.
- **원자적 클레임**: 코드 슬롯 증가와 유저 생성을 한 트랜잭션에 묶는다. 따로 두면
  "코드는 소모됐는데 가입 실패"(코드 유실)가 생긴다. 슬롯 경쟁은 `points.redeem` 과
  같은 조건부 UPDATE 로 직렬화한다.
- **로그인은 무관** — 기존 가입자는 영향받지 않는다.

### 색인은 유지한다 — 방어는 게이트 하나뿐이다
전환 초안은 전역 `noindex` 였으나 **철회**했다. 등급분류 의무의 기준은 "유통 또는 이용에
제공"이고, 초대 코드가 없으면 이용 제공이 실제로 차단된다. 검색 노출은 요건이 아니다 —
시험용 게임물 제도도 **기간(60일)·인원(2만)**으로 규정하지 색인 여부를 보지 않는다.

반대로 색인 차단에는 실질 비용이 있다. 지금 병목이 유입 0인데, 랜딩 색인은 **초대 요청
리드를 받을 유일한 채널**이다. 검색으로 들어온 사람이 플레이할 수는 없고 요청만 할 수 있다.

- 랜딩(`/`)·`/terms`·`/privacy` 색인 허용, sitemap 유지
- 실제 이용 제공이 일어나는 `/play` 만 차단 (`robots.ts` Disallow + 페이지 noindex, 기존 그대로)
- 메타 카피를 초대제 실태에 맞춤 — 검색 스니펫에서부터 "비공개 테스트 참가자 모집"으로
  읽히게 해 방문자 기대와 "일반 제공 목적" 오해를 함께 줄인다

잔여 노출 리스크(신고 기반 검토에서 노출이 클수록 신고 확률↑, 적극적 SEO 가 유통 목적의
정황이 됨)는 **정도의 문제이지 요건이 아니다.** 게이트가 실질이다.

**함정 기록**: page metadata 는 layout 을 **덮어쓴다(병합 아님)**. 초안에서 layout 에만
noindex 를 걸었더니 자체 `robots` 를 가진 랜딩에는 안 걸려, 정작 유일하게 색인돼 있던
페이지가 그대로 노출됐다(실측으로 발견). 색인 정책을 손댈 때는 양쪽을 함께 본다.
