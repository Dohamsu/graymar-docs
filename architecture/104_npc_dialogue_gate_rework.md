# 104. NPC 대화 게이트 재설계 — 잡담 주입 · 대화 잠금

> 2026-08-18 · 상태: ✅ 구현·배포 (P1/P2 잔여)
> 관련: 불변식 23·26·41·42·44·50 · arch/45(잡담 모드) · arch/49(NpcResolver 단일 권한자) · arch/79 · arch/98

## 1. 배경 — 정성 리뷰에서 출발

"NPC 대사가 로봇 같지 않은지, 대화가 이어지는지, 맥락을 잡는지, 뜬금없이 단서를 주거나
주어진 대사만 반복하지 않는지"를 실측 런으로 확인한 것이 출발점이다.

**표본**: 3개 런 70턴 서술 **전문 정독** + `turns.llm_prompt`(주입 블록) · `llm_speech_audit`(어체) ·
`content/*/npcs.json`(화제 원문) 3소스 대조.

| 런 | 팩 | 턴 | 성격 |
|----|----|----|------|
| `a90e774b` | graymar_v1 | 35 | 실유저, 08-14 |
| `8ea665f7` | star_sand_v1 | 20 | playtest |
| `3616e8b8` | graymar_v1 | 15 | playtest |

**결론: 문장력은 문제가 아니었다.** 감각 묘사·문체·단서 발견 서술은 상용 수준이다.
로봇처럼 읽히는 지점은 문장이 아니라 **대화의 구조**였고, 사용자가 관찰한 4개 증상
(로봇 같다 / 대화가 안 이어진다 / 맥락을 못 잡는다 / 같은 대사 반복)은 서로 다른 4개 버그가 아니라
**두 게이트에서 갈라져 나온 같은 뿌리**였다.

두 결함 모두 **"문서에 적힌 규칙이 구현에 없다"** 는 같은 종류다.

## 2. P0-1 — 대화 잠금이 17턴 유지된 경로

### 2.1 증상

`NPC_BG_CUSTOMS`(피터슨, **tier=BACKGROUND**, `daily_topics` 2개)가 T4~T20 사실상 전 구간 주 화자.

| NPC | tier | 화자 턴 | 대사 | 어체 위반율 |
|---|---|---|---|---|
| NPC_BG_CUSTOMS | **BACKGROUND** | **17** | 28 | **28.6%** |
| NPC_MAIREL | CORE | 15 | 31 | 9.7% |
| NPC_HARLUN | CORE | **1** | 1 | 100% |

35턴 중 **2명이 32턴**을 점유했고, 배경 인물이 말하는 동안 CORE 하를런은 11턴 등장하고도 발화 1회
(*"친근하게 말을 건넨다"* 로 문단이 끝나고 대사가 없는 미완결 등장 8회).
**세관원과 17턴 대화해 얻은 fact 는 0건**이었다 — 단서는 전부 환경 묘사에서 나왔다.

### 2.2 근인 ① 연속 카운터 부재

```js
// (구) npc-resolver.service.ts findConversationLock
const windowStart = Math.max(0, ctx.actionHistory.length - 4);
for (let i = ctx.actionHistory.length - 1; i >= windowStart; i--) {
  if (!prevNpc) continue;
  if (prev.dialogueAct === 'FAREWELL' || prev.npcFarewell === true) break;
  if (SOCIAL_ACTIONS.has(prevAction ?? '')) return prevNpc;  // 첫 회차에 return
  break;                                                      // 아니면 첫 회차에 break
}
```

루프는 **화자가 있는 첫 iteration 에서 반드시 return 또는 break** 하므로, 행동 분류 판정은
**직전 1건만 본다**. 불변식 26 의 *"최대 4턴 연속 유지"* 에 해당하는 카운터가 없었다.

> `windowStart` 가 전부 죽은 코드였던 것은 아니다 — `continue` 로 넘어가는 **무화자 턴의 스킵 한도**
> 로는 기능했다("대화 상대가 있었으나 이후 4턴간 아무도 화자가 아니면 만료"). 회귀 테스트
> `npc-resolver.farewell-lock.spec` 이 이 동작을 고정하고 있었고, 이번 리팩토링 중 실제로 결함을 잡았다.
> 아래 `ANCHOR_WINDOW` 로 보존한다.

### 2.3 근인 ② 잠금 갱신 집합이 문서보다 넓음

```js
const SOCIAL_ACTIONS = new Set([
  'TALK','PERSUADE','BRIBE','THREATEN','HELP',
  'INVESTIGATE','OBSERVE','TRADE',   // ← 불변식 26 정의에 없는 3개
]);
```

세관원 잠금 구간 17턴의 actionType: **OBSERVE 11 / INVESTIGATE 3 / TALK 2 / TRADE 1**.
대화 행동은 2턴뿐인데 잠금이 유지됐다 — 플레이어가 혼자 서류·봉인·수레 자국을 보던 턴 하나하나가
세관원과의 "대화"로 집계됐다.

### 2.4 근인 ③ tier 필터 부재

`findConversationLock`·`resolve()` 어디에도 `tier` 참조가 없었다. 불변식 23("BACKGROUND 는 배경만")은
**상황 생성 단계에만** 적용되고 화자 결정 단계에는 미적용이었다.

### 2.5 근인 ④ (결정타) 자기강화 루프

`nano-event-director.service.ts` 의 NPC 선택 시그널은 **else-if 체인**이다.

```js
if (ctx.npcLocked && ctx.lockedNpcId) { [NPC 고정] 변경 불가 }
else if (ctx.targetNpcId)             { [NPC 지정] }
else if (ctx.wantNewNpc)              { [NPC 전환] }
else if (ctx.npcConsecutiveTurns >= 3){ [NPC 피로] 다른 NPC 또는 환경 묘사 권장 }
```

**잠금이 걸려 있는 동안 `[NPC 피로]` 는 영원히 도달하지 못한다.** 이미 존재하던 완화 장치가
첫 가지에 가려져 무효였다. 결과:

```
잠금 → [NPC 고정] → 선택지 4개가 전부 그 NPC 중심
     → 무엇을 골라도 OBSERVE/INVESTIGATE → SOCIAL_ACTIONS 포함 → 잠금 갱신 → 다시 고정
```

실측 T6~T20 선택지는 매 턴 4개 중 3개가 세관원 관련이고 **탈출구는 항상 "거점으로 돌아간다" 하나**였다.
*"그의 말을 무시하고 주변을 살핀다"* 조차 OBSERVE 라 잠금을 갱신했다 — **무시해도 벗어날 수 없었다.**

### 2.6 근인 ⑤ 지목이 잠금에 짐

Step 4(WEAK 별칭 부분 매칭)가 `if (!isChoice && !lockNpcId)` 로 **잠금 중 통째로 스킵**된다.
T9 *"투박한 노동자에게 다가가 물어본다"*, T29·T30 *"서기관에게 정보 요청한다"* 가 무시되고
잠금 NPC 가 답한 경로가 이것이다.

## 3. P0-2 — 잡담 화제가 긴장 장면에 매 턴 주입

### 3.1 증상

실측(`a90e774b` · `llm_prompt` 의 `[NPC 일상]` 블록): **35턴 중 24턴(69%) 주입, 그중 사교 발화 턴 0건.**
전부 OBSERVE / INVESTIGATE / PERSUADE / TRADE 였고 이동 턴(`go_hub`)에도 들어갔다.

- 밀수 서류 조작 흔적을 짚은 직후 — 세관원: *"습기가 너무 심해서 서류 잉크가 번지는군요. 관절마저 쑤셔 고생입니다."*
- 창고 잠입이 등불에 발각된 턴 — 마이렐: *"병영 식사가 또 부실하다는 보고가 올라왔소."*
- 플레이어가 협박한 턴 — 이렌: *"요즘 부두 생선 장수들이 값을 너무 올려서 걱정이에요."* (star_sand T15)

### 3.2 근인 ① 의도가 아니라 fact 파이프라인의 부산물을 봄

```js
if (!ctx.npcRevealableFact && !ctx.factHandoffHint &&
    !ctx.factWithheldHint && !ctx.factDefaultDescription &&
    ctx.dialogueAct !== 'FAREWELL' && ctx.dialogueAct !== 'THANKS' && targetNpcIds.size > 0)
```

원 설계(arch/45 Phase 2)의 프록시는 *"fact 키 매칭 0 = 아무 주제도 안 물었다 = 잡담 상황"* 이다.
이 프록시는 **TALK 턴에서만 성립한다.** OBSERVE·INVESTIGATE·SNEAK·THREATEN 턴은 애초에 대화가
아니므로 fact 매칭이 없는 것이 **정상**이고, 따라서 프록시가 **항상 참**이 된다.

### 3.3 근인 ② 이미 있는 판정기를 반대 방향으로 사용

`common/dialogue-act.ts` 의 사교 발화 집합(GREETING/WELLBEING/THANKS/FAREWELL)이 불변식 44 의
기준인데, 게이트는 그중 **2개만 제외 조건**으로 썼다. 감지기를 "켤 조건"이 아니라 "끌 예외"로만
사용한 것이며 GREETING/WELLBEING 은 참조조차 되지 않았다.

### 3.4 근인 ③ 소진 폴백이 증폭기

```
준비된 화제는 모두 다뤘습니다 — 지금 하는 일에서 파생되는 새 화제
(오늘 겪은 사소한 일·몸 상태·날씨 체감·일감 걱정)를 1~3문장 만들어 꺼내세요.
```

`NPC_BG_CUSTOMS` 는 `daily_topics` 가 **2개**라 T5·T6 에 소진되고 T7 부터 전 턴이 즉흥이다.
그리고 **프롬프트가 예시한 카테고리가 그대로 출력에 나왔다**:

| 턴 | 출력 | 카테고리 |
|---|---|---|
| T7 | "안개가 짙어 몸이 으슬으슬… 따뜻한 차 한 잔" | 날씨 체감 |
| T15 | "서류가 많아 눈이 침침할 지경" | 일감 걱정 |
| T17 | "습기가 심해… 관절마저 쑤셔" | 몸 상태 |
| T19 | "책상에 쏟은 찻물 때문에 밤을 꼬박" | 오늘 겪은 사소한 일 |

세관원 잡담 6종 중 콘텐츠 원본은 1종, **5종은 모델이 지어낸 것**이다.

### 3.5 근인 ④ 완성 문장 주입 → 축자 낭독

풀이 남아 있을 때는 반대 문제가 난다. `daily_topics` 가 완성 문장이라 그대로 낭독된다.

| `npcs.json` 원문 | 출력 |
|---|---|
| "병영 식사가 또 부실하다는 보고가 올라왔소. 부하들 배가 등에 붙으면 내가 무슨 명령을 하겠소." | T23 **거의 100% 동일** |
| "북부 전선에서 사흘을 굶으며 진군한 적이 있소. 그때에 비하면 이 도시는 천국이오." | T24·T33 재사용 |
| "단 가문의 이름이 무겁다고 사람들이 말하오…" | T30 거의 동일 |
| "잠은 네 시간이면 족하오." | T26 그대로 |

불변식 41·42·50("구체 어휘 주입 = anchor")이 `personality.signature`·`speechStyle` 에는 적용됐는데
**`daily_topics` 만 예외로 남아 있었다.** 즉 **풀이 있으면 낭독, 없으면 즉흥이고 중간이 없었다.**

### 3.6 두 결함의 곱셈

```
잠금 무한 유지 → 화자 1명 고정 → 그 NPC 풀만 소모
→ BACKGROUND 는 풀 2개 → 3턴 만에 고갈 → 즉흥 폴백 → 17턴 연속 즉흥 잡담
```

**반증 사례**: `3616e8b8` 은 화자가 4명(전부 CORE, 풀 10개씩)으로 분산돼 소진이 없었고,
같은 게이트·같은 모델인데 잡담 이질감이 훨씬 덜하다. **화자 편중이 잡담 결함의 강도를 결정한다.**

## 4. 구현

설계 원칙은 **끄지 말고 조건을 옮긴다** 였다. 두 게이트는 각각 실재하는 문제를 막고 있다 —
잠금은 NPC 점프(arch/49), 잡담은 NPC 가 정보 자판기가 되는 것(arch/45). 제거하면 그쪽이 회귀한다.

### 4.1 잡담 게이트 — `src/llm/small-talk-gate.core.ts` (신규)

블랙리스트(기본 ON, 2개 예외) → **화이트리스트**(기본 OFF, 사교 신호에만 ON).

| 판정 | 조건 |
|---|---|
| 차단 | 대상 NPC 없음 / fact 파이프라인 활성 / FAREWELL·THANKS |
| **허용** | dialogueAct ∈ {GREETING, WELLBEING} **또는** actionType === `TALK` |
| 차단 | 그 외 전부 (actionType 불명 포함 — 모르면 안 한다) |

허용 범위를 `TALK` 로 좁힌 근거: PERSUADE·TRADE·HELP 는 목적 있는 대화라 잡담과 경쟁하고,
반대로 TALK 을 빼면 arch/45 원 의도가 사라져 NPC 가 정보 자판기로 회귀한다.

`actionType` 소스는 `serverResult.ui.actionContext.parsedType` — `LlmContext.intentActionType` 신설.
legacy `actionType` 필드는 **항상 null** 이므로 쓰지 않는다(arch/100 §14 사문 배선, 실측 확인).

### 4.2 소진 폴백 제거 + 원문 인용 금지

- 폴백 삭제 → 화제가 없으면 **블록 자체를 넣지 않는다**
- `평소 화제 (참고)` → `화제 소재 (참고)` + *"위 문장을 그대로 옮기지 마세요. 소재만 가져와
  지금 상황에 맞는 새 문장으로 말하게 하세요"*

### 4.3 대화 잠금 — `src/engine/hub/conversation-lock.core.ts` (신규)

2상태 → **3상태**. 기존은 `갱신`/`해제` 뿐이라 OBSERVE 를 **어디에 넣어도 문제**였다
(갱신 = 무한 연장, 해제 = "대화 중 주변을 보면 상대가 바뀜" 회귀).

| 상태 | 행동 | 효과 |
|---|---|---|
| **RENEW** | TALK·PERSUADE·BRIBE·THREATEN·HELP | 유지 + streak +1 |
| **HOLD** (신설) | OBSERVE·INVESTIGATE·SEARCH·TRADE·REST | 유지, streak 불변 |
| **BREAK** | FIGHT·STEAL·SNEAK·MOVE_LOCATION 등 | 해제 |

- 상한: CORE·SUB **4**(불변식 26) / **BACKGROUND 0**(불변식 23 — 잠금 대상 제외)
- `ANCHOR_WINDOW = 4` — 무화자 턴 스킵 한도(구 `windowStart` 동작 보존)
- 상한 도달은 **소프트 해제** — 잠금만 풀고 배제하지 않는다(이벤트로 재등장은 자연스러운 재개)
- 상태를 저장하지 않고 **매 턴 재계산** (jsonb CAS 경합 표면을 늘리지 않음)

BACKGROUND 를 잠금에서 뺐다고 발화가 막히는 것은 아니다 — 명시 지목 턴에는 NpcResolver
Step 0~3(텍스트 매칭)이 그 턴 화자로 세운다. "배경 인물과 말은 섞되 붙잡히지는 않는다."

### 4.4 복제 drift 차단

`findLockFromHistory`(nano·COMBAT 용)와 `findConversationLock`(resolve 내부)이 **같은 로직을 복제**
하고 있었다. 한쪽만 고치면 nano 와 resolver 의 잠금 판정이 갈라진다(arch/67 에서 겪은 구조).
둘 다 `NpcResolverService.getLockState()` → core 로 수렴시켰다.

### 4.5 자기강화 루프 차단

`[NPC 고정]` 분기 안에서 `streak >= limit - 1` 이면 `[전환 예고]` 를 병기한다 —
*"선택지 중 최소 하나는 다른 인물·장소·행동으로 향하게 하세요."*
화자는 잠금 NPC 로 유지하되 선택지만 바깥으로 연다. 잠금이 4턴에 풀리므로 이후는 기존
`[NPC 피로]` 분기로 자연히 넘어간다.
