```bash
LLM_PROVIDER=openai
OPENAI_MODEL=google/gemma-4-31b-it
OPENAI_BASE_URL=https://openrouter.ai/api/v1
LLM_FALLBACK_MODEL=openai/gpt-4.1-mini
LLM_ALTERNATE_MODEL=deepseek/deepseek-v4-flash-0731  # 교차 (v3 부록 D, 0731 스냅샷은 부록 D-9)
```

### E-5. live P0 — fallback 층이 3주간 죽어 있었다

```
openai/gpt-4.1-mini + penalty, require 없음            → 200 (Azure)
```

메인 서술(Gemma)의 레버는 그대로 보장된다.

## 부록 F. Gemini 3.x 후보 평가 — 3.6-flash 탈락 · 3.5-flash-lite 보류 (2026-08-14)

> **📕 트랙 종결** — F-9 참조. 품질 개선 목적이었으나 품질 축에서 개선이 없어
> 소유자 판단으로 모델 교체 트랙을 닫았다. 재개 조건은 F-8·F-9.

> **결론**: 둘 다 채택하지 않는다. `gemini-3.6-flash` 는 **추론을 끌 수 없어** 구조적
> 결격이고, `gemini-3.5-flash-lite` 는 속도가 압도적(p50 2.2배 빠름)이지만 **서술이
> 24% 짧고 비용이 47% 비싸다**. 남는 것은 서버 수정 1건(Gemini 3.x reasoning 분기)과
> 도구 결함 2건이며, 이 셋은 반영했다.
> **표본**: 재생 15건(부록 E 는 40건 — 직접 비교 불가) + 실런 15턴 × 2(후보·대조군).

### F-1. 카탈로그 현실 — `gemini-3.6-flash-lite` 는 없다

`3.6-flash` 와 `3.5-flash-lite` 를 대상으로 했다.

### F-2. 라우팅 최적화 — flex 티어와 Vertex 배제

`gemini-3.5-flash-lite` 는 **엔드포인트가 7개**이고 서비스 티어로 단가가 갈린다.

  로그에는 아무 흔적이 없다.
- **`sort=price` 로는 flex 를 못 잡는다**(4.50원 유지). 태그를 `only` 에 직접 박아야
  절반 단가가 나온다. 그리고 flex 는 **느려지지도 않았다**(오히려 -11%).

### F-4. `gemini-3.6-flash` 탈락 — 추론을 끌 수 없다


Luna 는 `effort: none`, Gemini 2.5 는 `reasoning.max_tokens: 0` 으로 껐는데 3.6 은

- 출력 토큰의 **87%가 추론**(1,423 / 1,643). 추론은 출력 단가로 과금된다.
- **20.91원/턴** — 현행의 13.8배. 채팅 1턴 5p 모델에서 성립하지 않는다.

형식 준수(라벨 100% · 합쇼체 0)는 완벽했으나 나머지가 전부 결격이다.

### F-5. 실런 15턴 + 대조군 — 귀속을 분리한다

후보 런은 `LLM_ALTERNATE_MODEL` 을 비워 **교차를 차단**했다(안 끄면 짝수 턴이 Luna 로

**대조군이 반드시 필요했다.** 후보 런 직전 서버 레포에 타 세션 커밋 5건이 들어왔고,
그중 `db73039 perf(llm): V12 프롬프트 다이어트 5차` 가 있다. 후보 런이 14/14 를 찍었지만
**그게 모델 덕인지 그 커밋 덕인지 구분되지 않는다.** 같은 코드(`96848ff`) · 프로덕션
설정으로 대조군을 돌려 분리했다.

| 지표 | **3.5-flash-lite**(교차 차단) | **Gemma+Luna**(대조군) |
|---|---:|---:|

  매 런 실패하던 게이트가 통과한 것은 프롬프트 다이어트 커밋 덕이다.
- **모델에 귀속되는 차이는 V9(반복) 하나뿐**이고, 1런 대 1런이라 확정할 수 없다.

### F-6. 서버 수정 — Gemini 3.x 는 reasoning 필드를 붙이면 안 된다

첫 실런에서 **모든 메인 호출이 400 → fallback 강등**됐다(`llm_model_used` 전량
`gpt-4.1-mini`). 서버가 `model.includes('gemini')` 조건으로 무조건
`reasoning: { max_tokens: 0 }` 을 보내는데, 3.x 는 이를 거부한다.

`geminiAcceptsReasoningDisable(model)` 로 버전 분기 — 2.x 는 기존대로 끄고, 3.x 이상은
필드를 붙이지 않는다. 이 수정이 없으면 **어떤 Gemini 3.x 후보도 평가 자체가 불가능**하다.
유닛 3케이스 추가.

> 부록 E-5(fallback 404)와 같은 부류다: 모델별 파라미터 수용 범위를 코드가 모르면
> 메인이 조용히 죽고 fallback 이 대신 답한다. 이번엔 `llm_model_used` 귀속 확인이
> 없었으면 "gemini 가 잘 돌았다"고 오판할 뻔했다.

### F-7. 도구 결함 2건 추가 (E-8 연장)

7. **하네스가 운영 provider 라우팅을 재현하지 않았다** — 운영은
   `LLM_PROVIDER_ONLY_MAP` 으로 Gemma 를 4곳으로 묶고 `sort=throughput` 으로 고르는데,
   하네스는 무제약이라 느린 곳에 붙었다. 같은 모델·같은 시기에 **하네스 p50 8,378ms vs
   운영 3,165ms**. allowlist 가 걸린 모델만 불리해져 신규 후보가 과대평가된다.
   → `provider_routing()` 으로 `server/.env` 를 그대로 재현(`--no-routing` 으로 해제).
8. **`.env` 인라인 주석이 값에 섞였다** — `LLM_PROVIDER_ONLY_MAP=...CoreWeave  # 설명`
   에서 주석까지 프로바이더 이름으로 들어가 allowlist 가 깨진 채 요청이 나갔다.

재검토 조건: ① 레이턴시가 실제 이탈 요인으로 계측되거나 ② 짧은 서술이 프롬프트로

## 부록 G. GLM 5.3 Flash 후보 평가 — 보류 (2026-08-27)

F-9 로 닫은 것은 "**같은 후보**를 다시 재지 않는다"이지 신규 모델 등장까지 막은 것이
아니다. `z-ai/glm-5.3-flash` 는 2026-08-26 출시된 신규 모델이라 그 범위 밖이고,
소유자 지시로 조사·환경 세팅을 수행했다. **결론은 F-9 의 판단을 다시 지지한다.**

### G-1. 판정

| 축 | GLM 5.3 Flash | Gemma 31B (대조군) |
|---|---|---|
| 원/턴 (분석단가) | Novita 1.30 · BaseTen 2.87~3.18 | **1.32** |
| ms p50 / p90 | Novita 16,344/19,168 · BaseTen 7,119~8,611/9,191 | **6,613 / 9,981** |
| 라벨 준수 | Novita **66.7~76.3%** · BaseTen 85.7~100% | **100%** |
| 합쇼체 위반 · 절단 | 0 · 0 | 0 · 0 |
| 본문 | 600~700자 | 457자 |

실프롬프트 15건(`turns.llm_prompt`, 중앙값 15,783자) 재생. temperature 0.8 ·
penalty 0.4/0.3 · max_tokens 2048. **대조군을 같은 세션·같은 프롬프트로 함께 돌렸다**
(부록 E 의 "코드 변경이 섞이면 귀속이 무너진다" 교훈).

카탈로그 스펙은 매력적이다 — 컨텍스트 1.31M, 입력 $0.075/M(Gemma $0.09 보다 싸다),
penalty·temperature·seed 전부 지원. 서술도 Gemma 보다 34% 길다. 그런데:

**라벨 준수가 DeepSeek 탈락 구간(74.8~77.5%)이고 실패 양상도 같다.** 화자 없는 배경
대사를 서술에 인라인으로 박는다 — 무마커 대사는 초상화·화자 표시가 둘 다 실패한다.

```
…짐꾼 차림의 두 사람이 통나무 등 뒤에 붙어 손짓으로 도형을 그리고 있었다.
"…매일 통로가 새로 그려진다더군."
"그럼 지도를 가진 자 없인 못 들어간다는 얘기 아니냐."
```

같은 15건에서 Gemma 는 인용 17건 전부에 라벨을 붙였다. GLM 은 38건을 뽑고 **초과분이
정확히 이 무라벨 잡담**이다. 서술이 긴 것도 상당 부분 여기서 온다.

### G-2. 추론을 끌 수 없다 — 그런데 기본값이 max

`effort:none` · `enabled:false` 둘 다 400 `"Reasoning is mandatory for this endpoint
and cannot be disabled."` (F-4 의 `gemini-3.6-flash`·ox-alpha 와 같은 부류).
지원 effort 는 `max|high|low` 뿐이고 **기본값이 `max`** 다.

기본 상태로 부르면 추론이 5,045~5,470자를 뽑아 max_tokens 를 통째로 소진한다:

| 상태 | 본문 | TTLT | TTFT |
|---|---:|---:|---|
| 추론 필드 미지정 (기본 max) | **0자** | 29,532ms | **콘텐츠 델타 없음** |
| `reasoning:{effort:"low"}` | 정상 | 4,855ms | 1,010ms |

TTFT 가 아예 발생하지 않으므로 운영에서는 `LLM_FIRST_TOKEN_TIMEOUT_MS`(5s)에 전 턴이
걸려 fallback 강등된다. **끄는 게 아니라 낮추는 게 답인 부류** —
DeepSeek(`enabled:false`)·Gemini 2.x(`max_tokens:0`)와 대응 방식이 다르다.

### G-3. 프로바이더가 단가·속도·품질을 전부 가른다

같은 모델·같은 8건·같은 파라미터인데 프로바이더로 결론이 뒤집힌다.

| 프로바이더 | 티어 | p50 | 라벨 | 원/턴 |
|---|---|---:|---:|---:|
| Novita | 저가 $0.075/$0.25 | 18,402 | 66.7% | 1.08 |
| Z.AI¹ | 저가 | 15,852 | 66.7% | 1.28 |
| Io Net | 고가 $0.15/$0.50 | 38,723² | 66.7% | 2.50 |
| **BaseTen** | 고가 | **7,119** | **100%** | 3.18 |

¹ penalty 미지원이라 penalty 없이 측정 · ² 429 다발

**penalty + `require_parameters` 가 저가 티어를 걷어낸다.** Z.AI·GMICloud 는 penalty
미지원이라 404 `"No endpoints found"` (부록 E 의 gpt-4.1-mini 404 와 같은 기전).
불변식 50 레버를 유지하면 저가 티어에 **Novita 하나만** 남는다 — 고정하지 않으면
`sort=throughput` 이 2배 단가로 샌다.

**429 가 잦다.** 출시 익일이라 용량이 얇다 — DeepInfra 전건, Io Net 5/8,
BaseTen 은 15건 재시도에서 10건. 지금 라이브 플레이테스트를 돌리면 실패 턴 오염이
섞여 수치가 성립하지 않는다.

### G-4. 남긴 것 (모델 채택과 무관하게 유효)

- **`LLM_REASONING_EFFORT_MAP` 을 모델 계열과 무관하게 적용** (server
  `model-capabilities.ts`). 이전에는 `resolveReasoningEffort` 가 OpenAI 추론 계열이
  아니면 env 맵을 읽기도 전에 `undefined` 로 빠져나가, **추론이 기본 ON 인 비-OpenAI
  모델을 운영값으로 길들일 방법이 자체가 없었다**. F-4 에서 Gemini 3.x 를 계열 분기로
  땜질한 것의 일반해다. 맵에 없는 모델의 기본 동작은 종전과 동일.
  `ReasoningEffort` 에 `'max'` 추가(수용 집합은 모델마다 달라 판정은 프로바이더에 위임).
- **`scripts/extract-bench-prompts.py` 신설** — `turns.llm_prompt` → `llm-config-ab.py`
  입력. 하네스에 추출 단계가 없어 매번 손으로 만들고 있었다. 런 테이블은 `runs` 가
  아니라 **`run_sessions`** 다(API 경로 `/v1/runs` 와 다름).
- **`llm-config-ab.py --only`** — 프로바이더 allowlist 오버라이드. 이게 없어서 처음엔
  "모델이 느리다"로 결론 낼 뻔했다. G-3 을 가른 스위치다.

### G-5. 판단

**보류.** 비용은 동급인데 라벨 준수가 DeepSeek 구간이고, 저가 티어는 penalty 제약으로
Novita 하나만 남는데 그게 16~18초다. BaseTen 이면 속도·라벨은 해결되나 2.2배 단가에
429 가 잦다. F-9 의 결론("품질 개선은 모델이 아니라 프롬프트·파이프라인 쪽")을 바꿀
근거가 나오지 않았다.

**재검토 조건**: ① 용량 안정화(429 소멸) 후 BaseTen 40건 재생에서 라벨 100% 유지 ②
저가 티어에 penalty 지원 프로바이더 추가. 그 전에는 재측정하지 않는다.

**표본 한계**: 재생 15건(BaseTen 은 429 로 5~8건)·라이브 파이프라인 미검증. 이 벤치는
오프라인 프롬프트 재생이라 스트리밍 분류기·마커 파이프라인·R5v2 후처리를 통과한 뒤의
실품질은 보지 않았다. 상세는 `playtest-reports/bench_glm_5_3_flash_20260827.md`.
