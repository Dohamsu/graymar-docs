# 134. B1 공개 참조 형식 — 프롬프트 계약 1차 수정과 재검증 (2026-09-28)

## 수정 범위

[[architecture/131_b1_semantic_binding_assessment_20260928|§131]]의 실런에서 최종 Nano 35개 중 20개가 `grounding.targetRef`에 `npcId`용 내부 NPC ID를 복사했고, 공개 정본 참조를 쓴 것은 4개뿐이었다. 같은 Nano 요청에는 클릭용 `npcId`와 공개 `NPC_PRESENT:{turn}:{index}`가 함께 있어 두 namespace가 혼재했다. 또한 JSON 형식 예시의 세 `grounding.intent`가 모두 `TALK`여서 두 번째 `INVESTIGATE`, 세 번째 `OBSERVE`의 affordance와 충돌했다.

- Track 2의 **실험 플래그 전용** 프롬프트에서 `npcId`는 클릭용 내부 ID, `grounding.targetRef`는 공개 정본 refId라고 명시했다. 현장 NPC를 대상으로 할 때는 공개 목록의 같은 표시명 `NPC_PRESENT`를 고르도록 안내한다. 대상이 없으면 `null` 규칙은 유지한다.
- 세 JSON 예시의 `grounding.intent`를 각 affordance와 같은 값으로 만들었다. 일반(플래그 OFF) 선택지 모드의 출력 계약은 바꾸지 않는다.
- 프롬프트 출력 경계 회귀가 수정 전 각각 실패하고 수정 후 통과했다. 이 변경은 서버의 잘못된 ID 자동 변환이나 후처리 차단을 추가하지 않는다.
- 최종 변경 파일 lint·서버 빌드·전체 Jest **241스위트/3106테스트 통과**(기존 1스위트·2테스트 skip)로 회귀를 확인했다.

## 보류·다음 판단

극야해안에서 namespace 혼동은 사라졌지만 그레이마르에서는 내부 NPC ID가 T4·T6·T13에 반복됐다. 또한 `FACT_TAMPERED_LOGS` 같은 **공개 목록에 없는 발견 가능 fact ID**가 T4~T7의 targetRef로 반복됐다. Track 2 프롬프트가 공개 정본 목록과 별도로 `[발견 가능 fact]`의 미공개 후보 ID, `[이 장소 NPC]`의 내부 ID를 계속 보여주는 구조적 혼선이 남아 있다. 이는 동일 증상의 반복으로 묶어 이번 회차에서 두 번째 문구 패치를 하지 않는다.

다음 설계는 선택지 생성에 필요한 클릭용 NPC ID를 유지하면서 **검증용 공개 ref namespace를 별도 typed 계약으로 분리**하고, 방향 생성에만 필요한 미공개 후보 fact ID를 Track 2에 계속 전달할 필요가 있는지 점검하는 것이다. 현재의 ‘같은 표시명으로 NPC_PRESENT를 고르라’는 문구도 동명이인·같은 호칭의 두 NPC를 구별하지 못하므로 서버의 턴별 ID 대응이 필요하다. 형식 변환으로 원본 오류를 숨기거나 raw ID를 무조건 승인하지 않는다. 소유자·매체·시점·비공개 사실 질문/단정의 의미 검증, 동일 표면 사람 판정, 플래그 OFF 지연 대조도 계속 열려 있다. B1 완료, B2 활성화, P3-2/P2-E 완료는 승인하지 않는다.
