# B1 후속 사람 판정의 평가 적격성

이 문서는 [[architecture/123_narrative_quality_master_plan|서술 품질 마스터 계획]] §59.3의 B1 진입 판단에 쓸 표본을 구분한다. 2026-09-29 후속 격리 런의 비공개 패킷 36개와 사용자 판정 원장 36개를 같은 `evidenceId`로 대조했다. 기존 §62의 41개 후보와는 다른 런이다. 기존 41개 표현 검토 결과를 이번 B1 분모에 합치지 않는다.

원본은 Git 무시 경로 `playtest-reports/archive/b1-followup-20260929/review/`에 있다. 패킷 SHA-256은 `ae2b6343f9297f17d08422c939ee6e87538cf55ef12cf79f00f2c6b737c258db`, 판정 원장 SHA-256은 `b37ad40bef7ecec3bdb62cc686a1ce0f0368f9fcf73c7b57ca440ae520586a9f`다. 두 원본 보고서, 캡처, DB 턴 목록을 입력한 `choice-grounding-review-packet.mjs` 재검증은 12턴·36선택지, `ALLOW 18 / REJECT 17 / PENDING 1`로 통과했다. #60은 행동 기반 시간·장소 이동 기능을 기다리는 사용자 보류 항목이다.

## 판정 축과 첫 시범 범위

사용자 `ALLOW/REJECT`는 최종 선택지에 대한 판단이다. 거부 이유가 문구·힌트인지, 클릭 시 행동·대상 계약인지, 둘 다인지는 별도 감사가 필요하다. 아래의 엄격 후보는 **분석자 분류**이며 사용자 판정을 바꾸지 않는다. 사용자 이유가 없는 거부 건에 새 사용자 이유를 소급 기록하지 않는다.

첫 B2 시범은 계획 §59.3에 따라 공개 `NPC_PRESENT` 대화와 열린 질문만 검토한다. 이번 최종 선택지 36개는 모두 `sourceNpcId`가 있고 ITEM 선택지는 0개다. 따라서 이 자료로 ITEM 가족을 승인하지 않는다. `sourceNpcId`는 단순 표시 메타가 아니다. `location-turn.service.ts`가 이를 `choiceNpcId`로 NPC resolver에 전달하므로, 물건이나 다른 사람을 살피는 라벨에 잘못 붙은 NPC ID는 실제 다음 턴의 상대를 바꿀 수 있다.

| 분류 | 그레이마르 | 극야해안 | 합계 | 번호 |
| --- | ---: | ---: | ---: | --- |
| NPC 행동으로 볼 수 있는 `ALLOW` 후보 | 8 | 7 | 15 | 43, 45, 46, 48, 51, 54, 56, 57, 59, 64, 66, 69, 72, 74, 76 |
| 행동·대상 불일치가 직접 확인되는 `REJECT` 후보 | 4 | 4 | 8 | 44, 47, 49, 53, 62, 65, 68, 71 |
| 보류 또는 B1 분모로 바로 쓰지 않을 판정 | 6 | 7 | 13 | 42, 50, 52, 55, 58, 60, 61, 63, 67, 70, 73, 75, 77 |

마지막 행에는 `PENDING`인 #60 하나와 판정된 12개가 있다. #50·#70·#77은 사용자 `ALLOW`를 존중하지만 첫 NPC 대화 평가에는 넣지 않는다. #50의 사례 제안은 `PERSUADE`로 저장돼 금전 지급을 실행하지 않는다. #70·#77은 문서의 줄을 살피는 행동인데 `sourceNpcId`는 사람이다. 이들은 사용자 판단을 뒤집지 않고 **계약 대조 필요**로 남긴다. #55·#67은 `대가`와 `PERSUADE` 사이의 같은 불일치 가능성이 있고, #52·#58·#61은 사용자 거부 이유가 없으므로 B1 결함 유형을 단정하지 않는다. #42·#63·#73·#75는 문구·장면 연결 또는 힌트 문제가 중심이다.

엄격 `REJECT` 8개 중 다수는 물건·주변 관찰을 NPC에 연결한 **범위 밖 경계 사례**다. 첫 시범의 NPC 대화 가족에 필요한 부재 NPC·잘못된 NPC 대화 참조의 균형 표본으로 자동 승격하지 않는다. 보수적 집계에서는 전체 `REJECT` 최소 10개에 2개 부족하고, 각 팩도 최소 5개에 1개씩 부족하다. 더 중요한 결손은 첫 시범 범위 안의 부재/잘못된 NPC 대화 반례와 ITEM 사례가 없다는 점이다. 단순히 두 건을 더 생성해 숫자를 맞춰도 §59.3을 통과하지 않는다.

격리 DB `graymar_luna_choice_run_20260929`의 두 원본 런에는 `choice-grounding-semantic-shadow` 호출 **12건**이 남아 있다. DB의 `llm_call_logs.calls`는 호출 단계·비용·지연만 보존하고 판단 결과는 보존하지 않는다. 현재 서버는 구조/의미 shadow의 상세 결과를 로그로만 출력하며, 사람 검토용 packet은 의도적으로 이 신호를 제외한다. 당시 일시 서버의 상세 로그 파일도 비공개 보존 디렉터리에서 찾지 못했다. 따라서 이 35건에 대한 구조·의미 미검출률이나 오차단률을 지금 계산할 수 없다. 호출 12건을 평가 완료 12건으로 세지 않는다.

## 다음 검증 관문

1. 이 35개 판정의 최종 라벨·전체 payload·같은 턴 정본을 고정한다. 분석자 분류와 사용자 판정을 별도 필드로 유지한다. 같은 턴의 구조·의미 shadow, 원 Nano 제안과 후단 변경, 실제 클릭 결과를 연결하지 못한 항목은 `UNVERIFIED`로 둔다.
2. 첫 시범 범위의 NPC 대화에 대해 각 팩에서 부재 또는 잘못된 NPC 참조의 최종 Nano 반례를 확보한다. ITEM은 별도 자료가 생기기 전까지 제외한다. 사건 확률에 맡긴 새 실런으로 분모가 채워지지 않으면 B1을 `HOLD`로 결론 내리고 범위를 더 좁힌다.
3. 적격 표본과 정책을 고정한 뒤 마지막 코드에서 두 팩 각 10~15턴의 두 번째 B1 실런을 수행한다. 동일 입력 OFF/ON의 전체 턴 p50·p95, 실패, 저장·노출·클릭·다음 턴을 따로 비교한다. 이 조건이 모두 충족되기 전에는 `PASS_LIMITED`, B2 시범, P3-2 완료를 선언하지 않는다.

이 문서는 기존 모델 품질 실런이나 자동 15/15 점수를 B1 통과 근거로 재해석하지 않는다. 비공개 원본의 서버 전용 참조와 개인 정보를 문서에 복사하지 않았다.

## 2026-09-29 후속: v3 증거 캡처와 새 두 팩 실런

기존 35개 판정의 누락된 당시 shadow 결과는 복원할 수 없다. 새 런부터는 최종 선택지 DB 저장 성공 뒤 같은 비공개 0700 디렉터리의 불변 0600 캡처에 Nano 원 후보, 생성 직후의 `ChoiceItem`, 최종 표면의 구조 shadow, 의미 shadow를 ID별로 보존한다. 기존 v2 캡처는 그대로 읽고, v3의 내부 판정은 사람 검토 패킷에 투영하지 않는다. 후보→최종 변환이 이후 원본 배열을 바꿔도 사라지지 않도록 생성 직후 깊은 사본을 잡는다. 이 변경은 실험 플래그와 캡처 디렉터리가 켜진 격리 런에만 적용되며 차단·노출 정책을 바꾸지 않는다.

격리 DB `graymar_luna_choice_run_20260929`와 3015 서버에서 그레이마르 `e33f3b57-429d-450d-93aa-c904d00f600b`, 극야해안 `c2b3a3b3-0a43-4ef4-9566-a1775dbb9c6b`을 각 10턴 실행했다. 운영 3000 서버와 운영 DB는 변경하지 않았고 3015 서버는 종료했다. 두 런의 자동 게이트는 각 15/15였지만 B1의 의미 합격 근거가 아니다. DB 읽기 전용 목록 28턴과 원본 보고서, 12개의 v3 캡처를 대조한 사람 검토 패킷은 최종 Nano **36개**를 포함한다. 36개 모두 생성 직후 후보가 연결됐고, 6개의 `ChoiceItem`은 생성 직후와 최종 저장값이 달랐으며 그중 라벨 변화는 1개다. 구조 shadow는 `STRUCTURE_MATCH 30 / CONTRADICTED 6`, 의미 shadow는 `TARGET_POSSIBLY_ALIGNED 12 / UNVERIFIED 24`였다. **이 기계 신호를 `ALLOW/REJECT`로 번역하지 않는다.** 비공개 원본은 `playtest-reports/archive/b1-v3-20260929/`에 있고, 사람 판정 원장은 아직 36개 전부 `PENDING`이다.

v3의 원 후보·구조·의미 필드가 패킷에 새지 않는 회귀 테스트와 서버 전체 Jest 243 suite·3,127 tests(기존 1 suite·2 tests skip), 빌드, 변경 파일 lint를 통과했다. 실런 뒤에는 **최종 Nano ID마다 원 후보가 반드시 있어야 한다**는 캡처·패킷 검사를 추가했고, 기존 새 런 자료 36개를 강화된 검사로 다시 통과시켰다. 이 사후 보강은 실런의 모델 출력이나 저장 선택지를 바꾸지 않았지만, 엄밀히 실런 시점과 최종 검증 코드의 바이트는 다르다. 새 런은 기록 품질과 클릭 연결을 확인한 것이지 §59.3의 두 번째 B1 판정 완료가 아니다. 다음 관문은 새 패킷의 독립 사람 판정과 NPC 대화 가족의 부재/잘못된 참조 반례 확보다. ITEM 자료와 동일 입력 OFF/ON 지연 대조도 여전히 없으므로 `PASS_LIMITED` 또는 B2 활성화는 보류한다.

## 2026-09-29 결론: B1 적용 승격 `HOLD`

사용자에게 새 36건을 전수 판정받는 작업은 중단했다. 기존 35개 판정으로 먼저 최종 클릭 대상과 라벨의 관계를 재검사했다. `server/scripts/choice-grounding-payload-target-replay.mjs`는 기존 12턴의 최종 payload가 가리키는 공개 NPC를 **새 합성 제안**으로 만들고, 현재 의미 판정기를 호출한다. 사람 판정은 호출 후 결과에 결합한다. 당시 Nano의 원 제안이나 당시 shadow를 복원하지 않으므로 아래 수치는 **과거 B1 검출률이 아니다**. 비공개 결과는 `playtest-reports/archive/b1-followup-20260929/review/payload-target-replay.json`에 0600 파일로 보존했다. 패킷과 원장 SHA-256은 이 문서 첫 문단의 원본과 일치한다.

| 분석자 분류 | 대상 불일치 신호 | 일치 가능 신호 | 미확인 | 합계 |
| --- | ---: | ---: | ---: | ---: |
| 허용 후보 | 0 | 8 | 7 | 15 |
| 행동·대상 불일치 거부 후보 | 1 | 0 | 7 | 8 |

그레이마르 거부 후보 4개 중 1개만 대상 불일치로 나왔고, 극야해안 거부 후보 4개는 모두 미확인이다. 전체 36개에서는 `TARGET_MISMATCH 1 / TARGET_POSSIBLY_ALIGNED 13 / UNVERIFIED 22`다. 재검사 12턴은 모두 `EVALUATED`였고 모델 응답의 기록 비용 합계는 `$0.000940632`다. 이 비용을 실제 청구액이라고 단정하지 않는다. 사람 판정이 문구·힌트 문제인 나머지 13개는 대상 일치 정확도의 분모에 합치지 않았다.

**현재 결론은 `HOLD`다.** 첫 NPC 대화 가족의 부재/잘못된 NPC 반례 균형이 없고, 합성 대상 재검사도 직접 불일치 후보 8개 중 7개를 승인이나 거부가 아닌 미확인으로 남겼다. ITEM 가족은 자료가 없다. 새 v3 런의 36개도 사람 판정 전이며, 동일 입력 OFF/ON 지연 대조는 수행하지 않았다. 이 상태에서 B2를 켜거나 미확인을 허용으로 취급하지 않는다. `HOLD`는 B1 평가의 현재 결론이며 문제를 해결했다는 뜻이 아니다. 새 36건의 전수 판정을 재개하지 않는다. 다음 개발은 사용자 판단을 더 모으는 대신 NPC 대화·행동 대상 계약의 고정 반례를 코드 경계에서 검사하고, 해당 범위가 실제로 개선된 뒤에만 소수의 독립 사람 판정을 요청한다.
