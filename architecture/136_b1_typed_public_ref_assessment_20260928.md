# 136. B1 Track 2 공개 참조 입력 분리 — 2차 수정·격리 검증 (2026-09-28)

## 변경 경계

[[architecture/134_b1_public_ref_prompt_assessment_20260928|§134]]의 1차 문구 수정 뒤에도 Track 2 Nano는 클릭용 내부 NPC ID 6건과 미공개 후보 fact ID 3건을 `targetRef`에 사용했다. 서버는 이들을 승인하지 않았지만, 실험의 의미 감사 분모에서 빠졌다. 이번에는 같은 문구를 더 늘리지 않고 **실험 플래그 전용 입력 계약**을 분리했다.

- 같은 턴 서버 카탈로그에서 모델용 `publicView`와 서버 보관 `NPC_PRESENT refId → 내부 npcId` 대응표를 별도로 만든다. 대응표는 모델 메시지에 직렬화하지 않는다.
- 실험 Track 2의 NPC 목록·선택지 `npcId` 형식·금전/거래 힌트는 공개 `NPC_PRESENT` 별칭을 쓴다. 모델의 선택지 `npcId`는 서버가 대응표로 내부 ID에 역변환한 뒤 기존 선택지 빌더·클릭 payload 경로에 넘긴다. `grounding.targetRef`는 **역변환하지 않고 원문 그대로** 구조·의미 shadow에서 검사한다. 모델이 제출한 원시 내부 ID·목록 밖 별칭은 클릭 NPC로 승인하지 않는다.
- 현장 목록 밖 NPC에는 공개 별칭이 없으므로 실험 선택지 프롬프트에서 그 인물의 금전·거래 선택지 강제 힌트는 생략한다. NPC 고정 문구도 현장 표시명이 없으면 내부 ID 대신 중립 호칭을 쓴다. 서버의 기존 NPC 잠금/정규화와 방향·기본 선택지 경로는 건드리지 않는다. 이 경계의 장기 해법은 현장 밖 정본 NPC의 공개 별칭 계약이다.
- Track 2의 검증용 공개 참조 목록은 유지하되, 방향 생성용 `[발견 가능 fact]`의 미공개 후보 ID·설명을 이 선택지 요청에서는 제외한다. Direction/기본 선택지 경로의 해당 입력은 바꾸지 않는다. 장면 본문·저작 힌트에 이미 공개된 사실까지 지우는 변경은 아니다.
- 출력 경계 테스트는 미공개 후보 ID 미노출, **동명 NPC 둘의 별칭 구별**, 정확한 내부 ID 복원과 최종 `sourceNpcId`, 구조 제안 원문 보존을 확인한다. 이는 실험 경로의 클릭용 ID 복원이지 자유 생성 라벨의 안전 승인 장치가 아니다.

## 실측

운영 서버·DB를 건드리지 않고 격리 DB `graymar_p3_e2e_20260927`·포트 3015에서 두 팩 각 10턴을 실행했다. 두 플래그만 ON이며 운영 기본값은 OFF다. 그레이마르 `268418f6-2e3f-46cb-9199-d8d8d5bcdfbb`와 극야해안 `99a66876-8fa0-40bd-83e5-668e345d5604` 모두 자동 게이트 15/15였다. 10개 shadow 턴의 최종 Nano 29개, 다음 테스트 입력으로 실제 클릭한 선택지는 6개다. 공개 목록, 후보·최종 라벨, 전체 payload, shadow 판정과 다음 입력은 [[architecture/135_b1_typed_public_ref_followup_20260928.json|§135]]에 보관했다. 이 런 뒤 코드 검토에서 원시 내부 ID 우회·현장 밖 NPC 힌트 경계를 발견해 위의 보수적 처리를 추가했고 단위 회귀로 검증했다. 따라서 §135는 **마지막 경계 보강 전 실런**이며 그 보강의 새 실모델 준수율은 아직 측정하지 않았다.

| 최종 Nano 표면 | 1차 수정 후 별도 런 §133 | 이번 2차 수정 후 별도 런 §135 |
| --- | ---: | ---: |
| 공개 목록의 targetRef | 15/36 | 21/29 (그레이마르 9/15, 극야해안 12/14) |
| 목록 밖 targetRef | 9/36 (내부 NPC 6·미공개 후보 fact 3) | **0/29** |
| targetRef 없음 | 12/36 | 8/29 |
| 구조 `STRUCTURE_MATCH` | 24/36 | 24/29 |

29개 중 `NPC_PRESENT` 대상 제안은 15개였다. 최종 클릭 payload의 NPC ID는 서버 내부 값으로 유지됐고, 극야해안 T13 한 선택지의 `NPC_PAYLOAD_MISMATCH`는 라벨/제안 대상이 견습공인데 생성 선택지의 클릭 NPC가 `null`인 **실제 구조 불일치**로 남았다. 모순을 별칭 변환으로 덮지 않았다. 구조 `CONTRADICTED` 5건에는 `INTENT_PAYLOAD_MISMATCH` 4건, `NPC_PAYLOAD_MISMATCH` 1건이 있고 `LABEL_CHANGED_AFTER_PROPOSAL`은 3건(이유 중복 집계)이다.

JEV 의미 shadow 신호는 `TARGET_POSSIBLY_ALIGNED 6 / TARGET_MISMATCH 1 / UNVERIFIED 22`였다. 극야해안 T13의 견습공 접근 선택지는 `targetRef=NPC_PRESENT:13:2`이지만 클릭 NPC가 없고, JEV도 라벨↔대상 불일치를 높은 확신(0.95)으로 표시했다. 반면 그레이마르 T13의 “책상 위 종이와 잉크 냄새”는 공개 `FACT:FACT_LEDGER_EXISTS`에 연결돼 구조 일치지만 JEV는 보류했다. 대상 의미 문제는 여전히 열려 있다. 10회 JEV 호출 지연은 200–329ms(중앙값 214.5ms), 합계 약 $0.00072였다. 플래그 OFF 동일 자극 전체 턴 지연 대조는 아직 없다.

이전 런과는 **확률적 장면·선택지 표면이 다르므로** 표 수치를 인과적 품질 개선율, 미검출률, 오차단률로 해석하지 않는다. 미공개 후보 fact가 다른 서술·힌트 경로에서 노출되는지까지 이 테스트가 증명하지는 않는다. 사람의 `REJECT/ALLOW` 동일 표면 판정도 아직 없다.

## 현재 판정

반복 항목 B1-R1의 **2/2번째 수정·재검증**에서 이번 두 팩의 공개 참조 형식 이탈은 관찰되지 않았다. 그러나 표본이 작고, 라벨↔대상 의미·소유자/매체/시점·최종 payload 정합과 클릭 시점 상태 재검증은 별개다. R1은 추가 문구·자동 ID 승인 없이 **관찰 보류**로 두고, 다음 구현은 B1의 같은 최종 표면 사람 판정과 의미 검증 계약을 우선한다. 이 결과만으로 B1 완료, B2 제한 활성화, P3-2/P2-E 완료를 승인하지 않는다.

**최종 로컬 검증:** 공개 별칭·동명 NPC·목록 밖/원시 ID·현장 밖 금전/거래/잠금 경계의 대상 테스트 51개, 서버 빌드·변경 파일 lint, 전체 Jest 241스위트/3,109테스트 통과(기존 1스위트/2테스트 skip), 양 저장소 diff check 통과. 3015 격리 서버는 종료했고 운영 서버는 재시작하지 않았다. 이 검증은 마지막 경계 보강 뒤의 실모델 런을 대체하지 않는다.
