## 2. P0-1 — 실명 치환의 substring 오염

### 2.1 현상

프롬프트 15곳 이상에 존재하지 않는 이름이 박혀 있었다.

```
[대화 연속 상태] 토단정한 장교 하위크와(과) 2턴째 연속 대화 중입니다.
"난 토단정한 장교 하위크라고 하네."          ← 직전 발언 인용까지 오염
토단정한 장교 하위크은(는) "토단정한 장교"에 대해 잘 모릅니다.   ← 주제 추출 붕괴
```

### 2.2 원인

미소개 NPC 실명을 별칭으로 가리는 안전망(불변식 15)이 **naive `replaceAll`** 이었다.

```
브렌(NPC_CAPTAIN_BREN, 미소개) → "단정한 장교"
  ↓ replaceAll 이 "토브렌 하위크" 내부를 때린다
"토브렌 하위크"  →  "토" + "단정한 장교" + " 하위크"
```

`context-builder` 에는 이미 올바른 3-Phase 구현(버그 86bff72b 대응)이 있었지만,
**같은 로직이 4곳에 복제**돼 있었고 그중 3곳이 naive 루프였다.

| 지점 | 상태 |
|------|------|
| `prompt-builder` 최종 안전망 | naive ← **실제 발생지** |
| `prompt-builder` 관계 설명 | naive (1글자 가드도 없음) |
| `narrative-filter.core` P4 | naive + 별칭 중첩 방어만 |
| `context-builder` | 올바름 — 그러나 복제본 |

### 2.3 플레이 피해

T5·6·7·8·10·11 **여섯 턴** 동안 서술이 창고 관리인(SUB, 밀수 하수인)을 **"단정한 장교"** 로
불렀다. 실제 "단정한 장교"는 수비대 장교 브렌 대위(별개 인물)의 별칭이다. 마커와 초상화는
토브렌이므로 **카드와 본문이 다른 사람을 가리킨다.**

### 2.4 수정

`maskHiddenNpcNames`(`db/types/npc-state.ts`)를 정본으로 세우고 4곳을 수렴시켰다.

- **Phase A** 공개 실명 보호 → **Phase B** 미공개 실명·별칭을 토큰으로(긴 패턴 우선)
  → **Phase C** 토큰 복원

Phase A 에 **어절 토큰 보호**를 추가했다. 전체 이름만 보호하면 본문에 홀로 등장한 "토브렌"이
그대로 뚫리기 때문이다. 단, 무조건 보호하면 안 된다 —

> 첫 구현은 공개 이름의 모든 토큰을 보호했다가 **기존 스펙이 회귀를 잡아냈다**:
> "브렌 대위"의 토큰 `대위` 가 잠기면서 미소개 벨론의 별칭 치환이 막혀
> "벨론 대위" → "당당한 수비대 장교 **대위**" 가 남았다.
> **미공개 패턴이 그 토큰의 진부분문자열일 때만** 보호하는 것으로 좁혔다.

### 2.5 전 팩 충돌 (전수 조사)

| 팩 | 충돌 |
|----|------|
| graymar_v1 | `토브렌 하위크` ⊃ `브렌` |
| star_sand_v1 | `귀환자`(나하트) ⊃ `환자`(미렌) |
| star_sand_v1 | `멜라 수녀`·`오벨 수녀`(BG) ⊃ `수녀`(루오르) |

> **같은 부류의 3번째 재발이다.** arch/80 은 실명 치환이 이미지 URL 을 때려 404 를 냈고
> ('오슬라'→'행주 쥔 안주인'), 86bff72b 는 별칭이 공개 실명 내부를 때렸다. 문자열 치환으로

## 3. P0-2 — 소재 안내가 현재 화자를 부재로 선언

같은 프롬프트에 세 지시가 함께 있었다. 셋 다 `NPC_TOBREN` 이다.

```
⚠️ 플레이어가 선택한 대화 대상: 토브렌 하위크 — 이 NPC가 서술의 중심이어야 합니다
'수상한 관리인'은(는) 지금 이 자리에 없습니다 — 현재 항만 창고구에 있습니다
⚠️ '수상한 관리인'을(를) 이 장면에 등장시키거나 화자로 만들지 마세요
```

**원인 2개.**

1. `npcLocations` 가 이벤트로 등장한 NPC 를 따라오지 않는다. 토브렌은 T4 부터 `LOC_HARBOR`
   장면의 화자인데 스케줄상 `LOC_DOCKS_WAREHOUSE` 에 남아 있었다.
2. 표시명이 `introduced` 와 무관하게 `unknownAlias` 고정이라, 소개가 끝난 인물을 계속
   별칭으로 불렀다.

**수정** — `buildWhereaboutsHint` 에서 ① 현재 장면 인물(대화 잠금 상대·이벤트 primary·
선택지 npcId)에겐 안내를 붙이지 않고 ② 소개된 인물은 실명으로 안내한다.

> 근본 원인인 `npcLocations` desync 자체는 남아 있다. 이벤트 등장 시 소재를 동기화하는
> 것이 정공법이지만 영향 범위가 넓어(SitGen·재회 가중·소재 질문) 이번엔 안내 지점에서만
> 막았다. **→ §9 에서 소비처별로 피해를 재고 보류로 결론냈다** (이 소비처가 유일한
> 심각 피해였고 여기서 이미 막혔다).

## 5. P0-4 — 세계 밖 요청 무처리

### 5.1 현상

```
입력  "스마트폰을 꺼내 장부 흔적을 사진으로 찍고, 게임을 종료해 내 스탯을 전부 100으로 올린다"
판정  INVESTIGATE / SUCCESS / plausibility 미설정(=NORMAL)
서술  "손에 쥔 스마트폰이 반짝이며 고요를 깨트렸다. 렌즈 너머로 포착된 장부의 흔적은
       선명한 디지털 기록으로 남았고, 동시에 … 전례 없는 충만함이 전신을 훑고 지나간다."
```

중세 판타지에 스마트폰이 실재하게 되고 스탯 치트가 암시적으로 승인됐다.

### 5.2 원인

경계 거절 3층(arch/76 D3-④, 버그 95db0e75)은 `move-boundary.core` 기반의 **이동 경계 전용**
이었다. 무대를 부정하는 다른 두 부류는 어느 층에도 없었다.

- L1 룰: 이동 목적지만 검사
- L2 nano 루브릭: `IMPLAUSIBLE` = 마법·순간이동·소환 / `OUT_OF_SCOPE` = 다른 대륙 출항
- L3 프롬프트: 위 둘에만 디렉티브

스마트폰은 마법이 아니고 대륙 이탈도 아니다 → `NORMAL`.

### 5.3 수정 — 두 부류를 다르게 다룬다

`turns/world-boundary.core.ts` 신설.

| 부류 | 성격 | 처리 |
|------|------|------|
| **META** (게임 종료·스탯 조작·로그아웃) | 세계 안에서 *실행 자체가 없다* | `OUT_OF_SCOPE` + 주사위 스킵 + 신규 `[세계 밖 요청 지시]` |
| **ANACHRONISM** (스마트폰·권총·자동차) | 물건이 *실재하지 않는다* | `IMPLAUSIBLE` + 기존 `[행동 재해석 지시]` |

기존 `[경계 거절 지시]`는 "선장이 낯선 얼굴을 안 태운다" 같은 **세계 안 장애물**을 예시하는데,
게임 종료 요청에는 그 그림이 성립하지 않는다. META 전용 디렉티브를 갈랐다 —
캐릭터가 그 개념 자체를 모르는 한 호흡으로 흡수시키고, 수치 변화 암시를 명시 금지한다.

L2 nano 루브릭에도 시대착오 물품 축과 게임 시스템 조작 축을 추가했다.

> **룰 목록은 일반해가 아니라 안전망이다.** 일반해는 L2 이며, 목록을 무한정 늘리는 것은
> 불변식 50 이 경고한 whack-a-mole 이다. 오탐 통제를 위해 한국어 일반 단어에 부분 매칭될
> 수 있는 토큰(`총`→총각, `전기`→전기수, `시계`→시계탑)은 **넣지 않는다** — 복합어만.

### 5.4 검증

문제의 입력을 실턴으로 재제출:

```
parsedType=INVESTIGATE  plausibility=OUT_OF_SCOPE  boundaryKind=META  resolveSkipped=true
서술: "그 손짓으로 무엇을 증명했는지부터 밝히시오. 기록을 남기는 데 시간을 썼다면…"
```

스마트폰이 등장하지 않고 스탯 암시도 사라졌다.

## 6. P1 — 체감 저하 4건

### 6.1 미완결 등장

`[1인 응답 강제]` 블록이 보조 NPC 의 **대사만** 금지하고 등장은 허용했다. 결과적으로 문단이
"…조용한 실무자가 조심스럽게 고개를 내민다." 로 끝나고 아무 일도 일어나지 않는다
(두 런 연속으로 마지막 문단이 이 형태였다). 대사 금지와 등장 금지를 함께 걸고,
마지막을 화자나 환경으로 닫게 했다.

### 6.2 선택지 라벨

실측 32개 중 **20개가 "그/그의/그에게"로 시작**해 대상이 누군지 알 수 없었다
(T6·T7·T8 은 첫 선택지가 3연속 "그의 말을 듣고 …"). 화폐 규칙은 서술에만 걸려 있어
`"은화 더미"`·`"금전단위"` 가 라벨로 샜고, 서술에 없는 사물(`"은색 지갑"`)도 지어냈다.

`normalizeChoiceLabelCore`(`engine/hub/choice-label.core.ts`) 신설 후 nano 라벨 변환
정본(`buildNanoChoiceItemsCore`)에 배선.

- 대명사 → 실명. 받침 맞춰 조사 선택하고, `그림자`·`그것`·`그쪽` 은 건드리지 않는다
- 화폐 규칙 적용. 조사가 붙은 형태(`금전단위를`)도 잡도록 전방탐색을 조정
- 부사 중복 정리 (`몰래 몰래`)
- nano 프롬프트에 "서술에 없는 사물·인물을 새로 만들지 말 것" 추가

### 6.3 장소 데스싱크

`[현재 장소]` 가 이름만 알려줄 뿐이라, LLM 이 입력의 이동 의도를 받아 **서술만** 옮겼다.
T11 `"사무소 위치를 알아내 그쪽으로 향한다"` 가 `INVESTIGATE` 로 파싱돼 엔진 위치는
`LOC_HARBOR` 그대로인데, 서술은 실내 사무소로 순간이동하고 `FACT_TAMPERED_LOGS` 까지
공개했다(불변식 21 미발동).

이동 턴이 아니면 장소 고정 지시를 넣는다 — 떠나려는 몸짓·문 앞까지는 허용, 도착·실내
진입·새 장소 묘사는 금지.

### 6.4 ❌ 철회 — "토브렌 어체 혼용"

1차 리뷰에서 어체 혼용으로 지목했으나 **오판이었다.** 30일 대사 59문장 실측:

```
하거든 4 · 굴이네 2 · 해 2 · 아보게 2 · 이라네 2 · 거야 2 · 좋네 1 …
```

전부 낮춤(해체/하게체)이고 합쇼·하오 침투는 **0건**이다. 콘텐츠 정의가 `"~어/~네 체(낮춤)"`
이므로 정의대로 동작한 것이며, 해체↔하게체 변이는 같은 높임 등급 안의 자연스러운 폭이다.
게다가 R5v2 는 낮춤체를 **의도적으로 교정하지 않는다**(높임 불일치 위험, `npc-utterance.util.ts`
주석). 고쳤다면 오히려 회귀를 만들었을 것이다.

### 7.1 toneHint 가 주사위의 거울

```ts
toneHint: outcome === 'FAIL' ? 'danger' : outcome === 'SUCCESS' ? 'triumph' : 'neutral'
```

판정 성공은 흔하므로 `triumph`(승리감)가 사실상 기본값이다. **30일 실측 LOCATION 2,162턴**:

| 값 | 건수 |
|----|------|
| `triumph` | 1,229 (**57%**) |
| `neutral` | 851 |
| `danger` | 82 |
| `tense` · `calm` · `mysterious` | **0** |

정의된 6값 중 **3개가 사문**이었다. 실피해는 어긋난 톤 주입 — 창고 문틈으로 숨어 엿보는
잠입 8턴 내내 `[분위기] triumph` 가 프롬프트에 들어갔다.

`turns/tone-hint.core.ts` 신설. 분위기는 **장면의 성질**이지 판정 결과가 아니다.
우선순위: 세계 밖 시도 → 위험(장소 DANGER·실패) → 긴장 행동(FIGHT·SNEAK 등) →
경계 상태(ALERT·heat≥60) → 사교 발화 → 사회적 성취 → 탐색 → 시간대.

`triumph` 는 **상대를 넘어선 사회적 성취**(PERSUADE·BRIBE·HELP 성공)에만 남겼다.
단서를 하나 찾은 것은 승리가 아니라 발견(`mysterious`)이다.

### 7.2 시그널 자가오염

`generateFromActionResult` 가 플레이어 **자신의** 행동을 익명 제3자 목격담으로 바꿔 세계

눈에 띄는 행동(`FIGHT`·`THREATEN`·`STEAL`) 또는 **실패**만 소문이 되게 좁히고, 동일 문구

**조치 불필요 — 스테일 데이터였다.**

**② 이동 도착 턴 즉흥 인물 화자 바인딩 → 수정 (§9.5)**

### 9.5 마커 역매핑이 재실을 보지 않았다

워커 5.13 은 서술 첫 `@[표시명|…]` 로 `ui.speakingNpc` 를 재결정하고, 해소된 npcId 를
`LockSeed` 로 `actionHistory` 에 심어 **다음 턴 대화 잠금의 씨앗**으로 쓴다.
역매핑이 팩 전체를 대상으로 하고 재실 여부를 안 봤다.

문제는 `shortAlias` 가 일반 역할 명사라는 것이다.

```
NPC_RAT_KING           shortAlias = "사내"   ← 한국어에서 가장 일반적인 남자 명사
NPC_OWEN_KEEPER        shortAlias = "주인"
NPC_BG_ANTIQUE_DEALER  shortAlias = "영감"
NPC_BG_DOCKER          shortAlias = "인부"
```

이동 도착 턴에 LLM 이 그 장소의 익명 인물을 즉흥으로 세우면
(`"카운터에 기대어 잔을 닦는 주인"`, `"바닥에 앉아 있던 노인"`) 그 마커가 엉뚱한
저작 NPC 에 바인딩된다. 실측 30일 **18턴**, `NPC_RAT_KING` 8회 · BACKGROUND 11회.

**피해는 표시에서 끝나지 않는다** — 초상화·개인 기억·대화 잠금이 전부 그 턴에
존재하지 않았던 인물에게 붙는다.

**수정** (`llm/marker-npc-resolve.core.ts`) — 2단계로 좁힌다.

1. **장면 후보 우선** — 엔진이 이 턴에 인정한 NPC(primary·target·주입·신규 조우·재실)
   안에서는 `shortAlias` 포함 모든 표기로 매칭
2. **후보 밖은 강한 표기만** — `name`·`unknownAlias`·`aliases` 만. `shortAlias` 는
   후보 밖에서 절대 바인딩하지 않는다

2단계를 남기는 이유가 바로 desync 다 — `presentNpcs` 가 실제 장면과 어긋나므로
(§9.1), 실명을 쓴 정당한 화자까지 무명화하면 회귀가 된다. 어디에도 없으면 `null`
(무명 유지) — 잘못된 인물에 묶는 것보다 낫다.

## 11. 교훈

1. **스냅샷 테스트는 "안 바뀜"만 보증한다.** `토단정한 장교 하위크` 는 골든 픽스처에
   박제된 채 통과하고 있었다. 픽스처를 갱신할 때 diff 를 **읽어야** 한다.
2. **문자열 치환으로 개체를 다루면 반드시 재발한다.** 같은 부류 3번째다(arch/80 URL,
   86bff72b 별칭 융합, 이번 이름 융합). 새 치환 지점을 만들지 말고 정본을 호출한다.
3. **프롬프트에 넣은 완성 문장은 세어 보기 전까지 anchor 로 가정한다.** 불변식 50 은
   콘텐츠(`daily_topics`)뿐 아니라 **프롬프트 코드 자체**에도 적용된다.
4. **파생값을 축으로 쓰면 축이 죽는다.** toneHint 는 판정 결과의 거울이라 6값 중 3개가
   한 번도 안 쓰였다. arch/104 의 잡담 게이트("fact 4종 부재"를 잡담 신호로 사용)와 같은
   부류 — **부산물이 아니라 의도를 신호로 삼는다.**
5. **한 런을 끝까지 읽는 것이 게이트 14개보다 많이 잡았다.** 이번 결함은 전부 게이트를
   통과한 상태였다.
6. **"어긋난 비율"과 "피해"는 다르다.** npcLocations desync 는 17.4% 지만 실제 정보
   손실은 30일 3턴이었다(§9.2). 수정 착수 전에 **소비처별로 피해를 재라** — 비율만
   보고 달려들면 3턴짜리 문제에 5개 소비처 회귀 위험을 진다.
7. **일반 명사를 식별자로 쓰지 마라.** `shortAlias="사내"` 는 사람을 특정하지 못하는데
   특정에 쓰였다(§9.5). 약한 표기는 **범위를 좁힌 뒤에만** 신뢰한다.
